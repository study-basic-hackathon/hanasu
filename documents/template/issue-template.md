# Issue テンプレート

GitHub Issue を起票・更新するときに、下の「テンプレート本体」を本文へコピーして使う。

運用方針の根拠は [検討記録: AI に実装させるためのタスク運用方針](../00_検討/20260808_AI向けタスク運用方針.md)。
**現時点の適用範囲は ytr-33 の担当分のみ**（チーム全体への展開は合意待ち）。

## なぜこの項目なのか

AI に「Issue #N を実装して」と渡すだけで着手でき、**AI 自身が完了を判定できる**ことを基準に選んでいる。
特に **「やらないこと」** は重要。AI は放っておくとスコープを広げるため、明示的な禁止が最も効く。

## 粒度の目安（1タスク = 1PR）

**1件に収める条件（すべて満たすこと）**

- 完了条件がチェックボックス 3〜5個以内で書ける
- 触る範囲が `frontend/` `backend/` `infra/` の**いずれか1つに収まる**
- 検証手段が1つに定まる（画面が表示される / テストが通る / API が 200 を返す）
- AI の 1〜2 セッションで実装から検証まで到達する見込み（目安: 新規 300 行 / 変更 200 行程度）

**分割の合図**

| 合図 | 分割の仕方 |
|---|---|
| タイトルに「〜と〜」が入る | 2件に割る |
| 未決事項がある（ライブラリ選定・方式選定など） | 「決める」Issue と「作る」Issue に割り、後者の「前提・依存」に前者を書く |
| フロントとバックの両方を触る | API 契約を決める Issue を先に立て、実装は別 Issue にする |
| 完了条件に「〜など」「一通り」が入る | 粒度以前に仕様が未確定。仕様起案の Issue に格下げする |

**細かすぎる合図** — 1ファイル / 1関数単位、「〜を確認する」だけの Issue。検証は実装 Issue の完了条件に含める。

## 記法のきまり

- タイトルは `[<領域>]<日本語の要約>`（`frontend` / `backend` / `infra` / `common`）— 現行の運用どおり
- ブランチは `feature/issue-<番号>-<英語スラッグ>`（例: `feature/issue-2-login-page`）
- PR 本文に `Closes #<番号>` を必ず書く
- 完了条件は**観測可能な形**で書く。「ログイン画面ができる」ではなく「`/login` にアクセスするとメール・パスワード入力欄が表示される」
- **リポジトリ内ドキュメントへのリンクは完全 URL で書く。** GitHub の Issue 本文では**相対リンクが機能しない**（Issue はファイルツリー上の位置を持たないため）。`https://github.com/study-basic-hackathon/hanasu/blob/main/<パス>` の形式を使い、日本語ファイル名は URL エンコードする

  ```bash
  # 完全 URL の作り方（パスを渡すとリンクを出力する）
  python3 -c 'import sys,urllib.parse; print("https://github.com/study-basic-hackathon/hanasu/blob/main/" + urllib.parse.quote(sys.argv[1]))' documents/ADR/0004-Nextjsプロジェクト初期構成.md
  ```

## テンプレート本体（ここから下をコピー）

````markdown
## 目的

<なぜやるか。1〜2行。AI が実装中の判断に迷ったときの拠り所になる>

## 完了条件

- [ ] <観測可能な形で書く>
- [ ] <3〜5個以内。超えるならタスクを分割する>

## やらないこと

- <このIssueで手を出さない範囲を明示する>

## 触る範囲

- `<ディレクトリ / ファイル>` — frontend / backend / infra のいずれか1つに収める

## 検証方法

```bash
<実行するコマンド>
```

## 前提・依存

- 依存Issue: #<番号>（先に完了している必要がある / なければ「なし」）
- 適用ADR: [ADR-XXXX](<相対パス>)（決定済みの方針。なければ「なし」）

## 未決事項

<未決がなければこのセクションごと削除する>

- 事前決定（必須）: <決めないと着手できない、または後から変えるとやり直しコストが高いもの>
- 事前決定（任意）: <後から変更が容易なもの>（推奨: <デフォルト案>）

## 参考

- [<ドキュメント名>](<リンク>) — <このタスクにどう効くかの一言>
````
