## 背景・きっかけ

現在の面接練習に加え、「何を言うか」だけでなく、「なぜその表現を選んだか」「相手と目的に応じてどう伝え方を変えるか」まで練習できるアプリへの拡張案が出た。

ユーザーから出た主なレッスン案は次のとおり。

- 表現力: 一つの事柄を説明し、表現を選んだ理由を AI が深掘りし、他の表現でも練習する
- 強調: 同じ文でも「今日」と「雨」のどちらを強調するかで伝わる焦点が変わることを練習する
- レポーター: 食べ物や情景を説明し、一次評価、AI の具体化質問、再レポート、二次評価、別解例の音読まで行う
- 滑舌: AI の見本を復唱する短い基礎練習を毎日行う
- 相手に合わせた伝え方: 同じ出来事を上司や友人などに伝え分ける。上司役は「結局何が言いたいのか」「何をすればよいか」を厳しめに確認する
- 日々の出来事を素材にし、練習と日記を兼ねる
- 身近な人や顧客に似た「聞き手ペルソナ」を保存し、同じ話を複数のペルソナ向けに伝え分ける
- ペルソナごとに実際の出来事と会話結果を記録し、「別の伝え方ならどうなったか」を再練習する
- 報告書やプレゼンに対し、複数の観客ペルソナが想定外を含む質疑を行う
- 学校の先生が AI 生徒に授業し、授業後の教え返しやテストによって、どこまで理解できた想定かを確認する

## 論点

### 必須

1. **プロダクトの対象範囲:** 面接対策を中心に伝え方の練習を足すのか、面接を一コースとする「伝える力のコーチ」へ広げるのか。
2. **学習単位:** 独立したレッスンのメニューにするか、診断と目標から毎日のメニューを出すコース型にするか。
3. **評価の単位:** すべてを一つの総合点にするか、レッスンごとの達成目標と能力マップで示すか。
4. **音声評価の範囲:** 強調・滑舌・抑揚を実際に自動評価するには、現行の文字起こしと発話時間中心の構成で足りるか、音響分析または音声を理解するモデルが必要かを検証する。
5. **初期提供範囲:** どのレッスンなら、技術的に誠実な評価と「練習前後で良くなった」体験の両方を最小で作れるか。
6. **ペルソナの定義:** 一般的な聞き手タイプ、実在人物を抽象化したコーチング用プロファイル、実在人物の再現のどこまでを扱うか。
7. **ペルソナと出来事の保存:** 第三者や職場の情報をどこまで保存し、匿名化、削除、保存期間、AI 利用目的をどう設計するか。
8. **AI 生徒の「理解」の扱い:** 実在生徒の学習効果測定ではなく、設定した予備知識・注意度・授業内容に基づく「理解したはずの範囲」のシミュレーションと明示するか。

### 任意

1. コース名、画面上のカテゴリ名、バッジや連続日数の表示。
2. レッスンの所要時間と一日の推奨回数。
3. 別解例をいつ見せるか、何例まで見せるか。
4. 厳しさの表示方法と、上司役のキャラクター。

## 事実確認（出典付き）

- 現行サービスのプライマリユーザーは選考を控えた求職者であり、主要価値は AI 面接官との模擬面接と話し方の定量評価である。面接以外の支援は非目標としている。出典: [ユースケース・ユーザーフロー](../ユースケース・ユーザーフロー.md) 3〜4章。
- 現行の練習メニューは「音読評価」「スピード測定」「一問一答評価」の3つである。音読のみが録音・一時評価の対象で、後者2つは画面モック、滑舌練習はメニュー非表示かつ実装対象外である。出典: [S-09〜S-13 練習モード](../frontend/01_design/screens/S-09-S-13_練習モード.md) 1章、3章、6〜8章。
- 現行の基本評価は「話の速さ」「フィラーの数」「構成・内容」の3項目である。話速とフィラーはコード、構成・内容は会話内容のみを受け取る LLM が評価する。出典: [評価仕様](../評価仕様.md) 2章。
- 現行の評価方針は、抑揚と声の大きさを評価対象に採用していない。また LLM には会話内容だけを渡し、定量実測値やスコアは渡さない。出典: [ADR-0009](../ADR/0009-評価方式.md) 2章。
- 音声と文字起こしは永続保存せず、現行の練習結果も画面内の一時表示である。日記や継続学習履歴を導入する場合、保存する内容とユーザーの削除手段は新たに決める必要がある。出典: [ADR-0009](../ADR/0009-評価方式.md) 2章 / [S-09〜S-13 練習モード](../frontend/01_design/screens/S-09-S-13_練習モード.md) 2章。

## 提案を整理する共通モデル

レッスンを個別に増やすより、すべてのレッスンを次の共通ループで作る案。

1. **意図を決める:** 誰に、何を、どう感じてほしいかを一つ決める
2. **初回実践:** 答えや見本を見せる前に話す
3. **根拠付き評価:** 良い点と、目標達成を妨げた点を実際の言葉や音声上の事実と結び付ける
4. **AI の問い返し:** 答えは与えず、不足している観点に気づく質問をする
5. **再実践:** 同じ題材でもう一度話し、初回との差を示す
6. **別解と模倣:** 複数の伝え方を比較し、一つを実際に読むまたは言い換える
7. **転移練習:** 似ているが別の題材で再現できるかを確かめる
8. **次の一点:** 次回に意識することを1つだけ持ち帰る

このループなら、初回と二回目の変化、ヒントの必要数、別題材での再現を、どのレッスンでも共通の学習指標として持てる。

### 共通単位の更新案: ペルソナ × 状況 × 目的

面接、上司報告、顧客説明、プレゼン、授業を別システムとして作るのではなく、次の要素を組み合わせる「対話リハーサル基盤」とする案が出た。

| 要素 | 例 |
|---|---|
| 話し手 | 求職者、担当者、プレゼン発表者、先生 |
| 聞き手ペルソナ | 忙しい上司、技術に詳しくない顧客、慎重な決裁者、予備知識の少ない生徒 |
| 状況 | 障害報告、商品説明、質疑応答、授業、謝罪 |
| 伝えたい目的 | 承認を得る、次の行動を依頼する、理解してもらう、不安を減らす |
| 成功条件 | 判断に必要な情報が揃う、要点を教え返せる、質問に誠実に応答できる |
| 実践形式 | 会話、スピーチ、報告書、プレゼン、授業 |

この単位で設計すると、「同じ話の核を保ちながら、聞き手に合わせて変えられたか」を共通の転移課題にできる。

### ペルソナの保存項目候補

実在人物の「デジタルコピー」を作るのではなく、伝え方の練習に必要な特徴だけを保存する。

| 分類 | 保存候補 |
|---|---|
| 関係 | 上司、顧客、同僚、友人、生徒、決裁者 |
| 予備知識 | その話題をどこまで知っているか |
| 関心・目標 | その人がまず知りたいこと、避けたいこと |
| 判断責任 | 最終判断者、助言者、実行者など |
| 好む詳細度 | 結論だけ、根拠まで、技術詳細まで |
| コミュニケーション傾向 | 質問が多い、あまり質問しない、反証を求める、時間を重視する |
| このテーマでの関心事 | コスト、品質、期限、安全性、納得感など |

氏名、連絡先、住所、社内識別子など、練習に不要な第三者の識別情報は保存対象から外す案を推奨する。実在人物の心理や次の反応を AI が正確に再現するとは表示せず、複数の起こりうる反応を試すコーチング用ペルソナとする。

## コース構成の候補

| コース | 育てる力 | レッスン例 |
|---|---|---|
| 声を整える | 届く声、滑舌、話速、間、強調 | 毎日の滑舌、シャドーイング、強調位置の言い分け |
| 言葉を選ぶ | 具体化、言い換え、比喩、語彙、情景描写 | 表現力、グルメレポート、五感による描写 |
| 話を組み立てる | 結論、理由、事実、要請、適切な長さ | 30秒 / 1分 / 3分の要約、一問一答、即興スピーチ |
| 相手に合わせる | 相手の前提・感情・必要な行動に合わせる力 | 上司への報告、友人への共有、専門家から初心者への説明 |
| 実践する | 複数の力を組み合わせる力 | 模擬面接、業務報告、プレゼン、レポート |

## ユーザー案の具体化

### 表現力レッスン

- 「赤い」と言った理由、「おいしい」をどの感覚で判断したかなど、AI は表現の根拠を質問する。
- 別解は「より具体的」「より感情的」「より簡潔」など、意図が異なる複数案にする。唯一の模範解答とは扱わない。
- 評価候補: 具体性、感覚情報、比較・比喩、目的と語彙の整合、冗長さ。

### 強調レッスン

- 最初は同じ短文を強調箇所だけ変えて聞き比べる。次に AI が意図を提示し、ユーザーが強調箇所を選んで読む。最後に自分の原稿へ移る。
- 「強く言ったか」だけではなく、強調した結果として聞き手がどんな含みを受け取るかを扱う。
- 評価候補: 意図した語の強調適合、不要な語の過度な強調、間とフレーズ分け、聞き手が受け取る焦点。
- 技術上の懸念: 音の大きさだけでなく、ピッチ、長さ、前後の間と単語位置の対応を見る必要がある。現行の文字起こし結果だけで達成判定しない。

### レポーターレッスン

1. 今食べているもの、眼の前の場所などを初回レポートする。
2. AI は「食感」「温度」「香り」「食べる前後の変化」など、不足している観点を質問する。
3. AI は答えを作らず、ユーザーが再レポートする。
4. 一回目と二回目の差を、言葉の詳細度と聞き手が情景を想像できる度合いで示す。
5. 最後に意図の異なる別解例を聞き、音読して表現と声の両方を練習する。

評価候補は、具体性、五感の使い分け、時間的な変化、比較・比喩、想像しやすさ、情報密度。実際に感じていないことを言わせないため、表現の豪華さより観察事実との整合を優先する。

### 滑舌レッスン

- 一日1〜2分のウォームアップとし、毎日のセッションの先頭に置く。
- 見本を聞く、ゆっくり復唱する、通常速度で復唱する、の順にする。
- 意味を持たない母音列や早口言葉は一般的な STT の文字一致率だけで発音を評価しない。自動評価が確立するまでは、実施回数、練習速度、自己評価などと分けて表示する。

### 上司への報告レッスン

クリア条件を「上司が全詳細を理解した」ではなく、「上司が次の行動または判断をできる」とする。上司役は、不足する要素があるときだけ短く問い返す。

| 評価観点 | 確認する内容 |
|---|---|
| 結論 | 何が起き、何を伝えたいかが早い段階で分かる |
| 影響 | 誰・何・期限にどれくらい影響するかが分かる |
| 緊急度 | いつまでに判断が必要かが分かる |
| 事実と推測 | 確定した事実と未確定の原因を混ぜていない |
| 現在の対応 | 行った応急処置と現在状況が分かる |
| 上司への要請 | 承認、判断、応援、共有のどれが必要かが明確 |
| 長さ | 必要事項を残したまま、目標時間に収まる |

最後は、ユーザーが実際に最後に言えた報告を全体評価し、「どの情報が加わったため上司が判断できるようになったか」を明示する。別解は「結論先行」「緊急度先行」「承認依頼先行」など目的の違いとして示す。

### 実際の出来事を再練習するレッスン

ペルソナとひも付けて、次のコーチング記録を保存する案。

1. どんな状況だったか。
2. 自分は何を伝えたかったか。
3. 実際にどう伝えたか。
4. 相手は実際にどう返し、結果はどうなったか。
5. 今回は何を改善したいか。

レッスンは「状況の再構成 → 初回の伝え直し → ペルソナの反応 → 表現選択の深掘り → 複数回の再挑戦 → 意図の異なる別解 → 最終実践」とする。

ただし、実際の相手の返信が不愉快だった事実だけで、「話し手の伝え方が間違っていた」と判定しない。AI は相手の内心を断定せず、伝え方を変えた場合に起こりうる複数の反応を提示する。

### プレゼン・報告書レッスン

プレゼンでは、1人の観客ではなく、異なる関心を持つ複数ペルソナを観客にする。

- 経営側: 費用、効果、期限、リスクを聞く
- 現場側: 手順、負担、例外、実現可能性を聞く
- 専門家: 根拠、前提、反例、数値の意味を聞く
- 初心者: 用語、目的、自分との関係を聞く
- 慎重な参加者: 失敗時、代替案、責任分界を聞く

想定外の質問は、単に突飛なものではなく、ペルソナの関心とプレゼン内容のどちらかに根拠を持たせる。「知らないことを誤魔化さず、どこまで分かり、何を確認して返答するかを言える」ことを信頼のプラス評価にする。

「信頼度」を一つの印象点にせず、次の根拠を分けて表示する案を推奨する。

| 観点 | 評価内容 |
|---|---|
| 正確性 | 説明済みの事実や根拠と矛盾していない |
| 質問適合 | 聞かれたことにまず答えている |
| 根拠 | 判断の理由または参照先を示せる |
| 不確実性の扱い | 未確認を断定せず、確認方法と返答予定を言える |
| 一貫性 | プレゼン本文と質疑回答の主張が食い違っていない |
| 相手適応 | ペルソナが必要な詳細度と用語で答えている |

報告書は「書いた内容を、読み手ペルソナがどう解釈し、次に何を確認したくなるか」をシミュレートする。原稿の添削だけでなく、読み手の質問に口頭で答える練習までつなげられる。

### 先生向け授業レッスン

有望だが、AI 生徒のテスト点を「実際の生徒が取るはずの点数」として表示するのは避ける。同じ LLM が授業全文を見たままテストへ答えると、理解ではなく「会話上に答えがある」ことを測ってしまう。

次の段階に分ける案とする。

1. **授業目標の登録:** 先生が「授業後に生徒が説明・判断・実行できること」を登録する。
2. **生徒ペルソナの設定:** 年齢だけでなく、予備知識、典型的な誤解、関心、注意状態、質問しやすさを設定する。
3. **授業の実施:** AI 生徒は設定に応じて反応する。「あまり質問しない」モードでは、授業中は分かったように進み、終了後に理解の穴を表面化させる。
4. **学習者ノートの作成:** AI は授業のうち、そのペルソナが拾えたと想定する要点、誤解、未接続の概念を分けて示す。
5. **教え返し:** AI 生徒が授業内容を自分の言葉で説明し、先生が意図した理解との差を見る。
6. **テスト:** 学習者ノートの範囲から AI 生徒が答え、別の評価処理が先生の授業目標と正答基準に照らして採点する。
7. **授業の振り返り:** 目標まで届いた説明、飛躍した説明、予備知識不足、例が逆に誤解を生んだ箇所をまとめる。

授業の評価候補は、学習目標の明確さ、予備知識の接続、説明の段階性、例と反例、誤解への対応、理解確認の機会、最後の要約。「半分聞いていない」はキャラクター演出ではなく、どの情報が学習者ノートに残らなかったかを追跡できる設定にする。

これは授業の弱点を見つけるシミュレーションであり、実在の生徒の理解度を保証する機能ではないことを表示する。

## 追加で考えられるレッスン

| レッスン | 練習内容 | 主な評価観点 |
|---|---|---|
| 同じ話を30秒 / 1分 / 3分で話す | 情報の取捨選択と詳細度の変更 | 結論の保持、重複、時間内、情報密度 |
| 聞き手を変えて説明する | 子ども、初心者、専門家に同じ内容を説明 | 前提知識、用語、例示、精度 |
| 一文結論トレーニング | 先に結論を一文で言い、詳細は後から足す | 結論の明確さ、質問との対応 |
| 言い換えトレーニング | 同じ意味を丁寧、親しい、簡潔、力強い表現で言う | 意味の保持、調子の達成、自然さ |
| 例え話トレーニング | 抽象的な話を日常の例に置き換える | 対応関係、分かりやすさ、誤解の少なさ |
| 質問にまっすぐ答える | 結論→理由→例の順で短く答える | 質問適合、結論位置、詳細過多 |
| 話を受け止めて確認する | AI の話を要約し、曖昧な点を質問する | 要約の正確さ、決めつけの少なさ、質問の有効性 |
| 難しい会話 | 断り、依頼、謝罪、異論を相手に伝える | 要望の明確さ、理由、配慮、代替案 |

## アプリ全体の流れの候補

### 初回

1. 主な利用目的を1つ選ぶ（面接、仕事の報告、表現力、日常会話など）。
2. 2〜3分の短い診断で、声、言葉、構成、相手適応の初期状態を見る。
3. 「最初の1週間で練習する一点」を提案する。

### 毎日（5〜10分）

1. 1分の滑舌または声出し。
2. 3〜5分のおすすめドリル。
3. 自分の原稿または今日の出来事を使う転移練習。
4. 初回と再実践の差と、次回の一点を確認する。

### 週次

1. 初見の題材で同じ力を使えるか確かめる。
2. 練習回数ではなく、どの力がヒントなしで使えるようになったかを振り返る。
3. 実生活で試す小さな課題を1つ決める。

## 評価設計の候補

一つの総合点だけではなく、次の4層に分ける案。

| 層 | 何を測るか | 指標例 |
|---|---|---|
| 発話の基礎 | 声が聞き手に届くか | 話速、フィラー、間、対象語の発音、意図した強調 |
| メッセージ設計 | 何をどう組み立てたか | 結論の明確さ、具体性、事実と意見、長さ、表現の意図適合 |
| 相手と目的への適合 | 相手が理解・判断・感情移入できるか | 必要情報の充足、用語、要請の明確さ、調子、情景の想像しやすさ |
| 学習 | フィードバックから学び、別の場面で使えるか | 一回目から二回目の改善、ヒント数、初見題材での達成、翌日・翌週の保持 |

表示は0〜100点に揃えるより、「未達 / ヒントありで達成 / 自力で達成 / 別の題材でも達成」の段階表示を主とし、話速など再現可能な定量値だけ数値で併記する案がある。

ペルソナ利用時は、次の差分も評価する。

- 聞き手を変えても、元の事実と主張の核を保てたか
- そのペルソナに不要な詳細を減らせたか
- そのペルソナが判断・理解するために必要な情報を追加できたか
- 用語、詳細度、例示、調子を変えた理由を自分で説明できたか
- 一人のペルソナ向けに学んだ方法を、別の聞き手にも転移できたか

## プロダクト評価指標の候補

### 最上位指標候補

**1週間に「初回実践 → フィードバック → 再実践」を完了した有効練習ループ数**。

単なる起動日数や録音時間ではなく、コーチングとやり直しまで完了した回数を見る。

### 学習成果

- 同じ題材の一回目と二回目の改善幅
- 同じ目標で必要な AI の問い返し・ヒント数の減少
- 初見の題材での達成率
- 翌日または翌週の再テストでの保持率
- ユーザーの予測評価と実際の評価の差
- 実生活で「伝わった」と報告された週次回数
- 同じメッセージを複数ペルソナ向けに適切に変換できた割合
- 実際の出来事を持ち込んだ後、似た別状況で自力達成できた割合

### 利用継続

- 初回レッスン完了率
- 1週間で2日以上練習したユーザーの割合
- 翌週継続率、4週継続率
- おすすめレッスンの着手率と完了率
- 別解例を見た後の模倣・転移練習まで進んだ割合

### AI 評価の品質

- 同じ入力に対する評価の再現性
- 人間の評価者と AI の評価の一致度
- 指摘した問題が実際の発言に根拠を持つ割合
- 具体的で次の試行で実行できる助言の割合
- 過度な称賛、不必要に攻撃的な返答、事実でない改善指摘の発生率

## 選択肢の比較

| 観点 | A案: 面接練習のまま拡張 | B案: 伝える力の総合アプリへ変更 | C案: 共通基盤を作り段階的に拡張 |
|---|---|---|---|
| 位置づけ | 求職者に限定 | 日常・仕事・面接を同時に対象 | 面接を実践コースとして残し、共通能力と他の実践コースを順次追加 |
| 既存構成との整合 | 高い | 大きな再設計が必要 | 一部は流用しながら境界を変えられる |
| ユーザー案との整合 | 上司・友人・日記を入れにくい | 最も高い | 高い |
| 最初の検証しやすさ | 高い | 低い | 高い |
| リスク | プロダクトの成長範囲が狭い | ターゲットと価値がぼやける | コース間の共通部分を早期に見極める必要がある |

**現時点の推奨は C 案。** ただし未合意であり、最初に面接以外のどの利用目的を検証するかは未決定。

## 初期提供範囲の推奨案

1. **第1段階:** 保存不要のプリセットペルソナ3人（忙しい上司、予備知識のない顧客、詳細を知りたい専門家など）に対し、同じ内容を伝え分ける最小レッスンで共通ループを検証する。
2. **第2段階:** 実名を不要とするカスタムペルソナ、表現の言い換え、別解比較、実際の出来事を持ち込む再練習を追加する。
3. **第3段階:** プレゼン質疑応答や授業シミュレーションなど、複数ペルソナが同時に参加する専門コースを検証する。
4. **第4段階:** 滑舌と強調の評価方法を検証し、妥当性を確認できた指標だけ自動評価に入れる。

強調レッスンは学習価値が高いが、現行の評価基盤で音声上の達成を測れるとは限らない。見本の聞き比べと自己評価から先に提供する場合でも、AI が音声を評価したように誤認させない表示が必要。

## 懸念

| 懸念 | 深刻度の感触 | 解消に必要な確認 |
|---|---|---|
| 面接対策と日常コミュニケーションを同時に掲げると、誰のどんな痛みを解決するかがぼやける | 高 | 最初のユーザー層と、最初に改善したい場面を1つ決める |
| レッスンごとに別のスコアを作ると、ユーザーが何を改善すればよいか分からなくなる | 高 | 一回の練習で指摘する改善点を1つに絞る原則を検証する |
| LLM の点数だけを比較すると、一回目と二回目の差が採点のゆらぎか実力向上か判別できない | 高 | 同一入力の再採点と人間評価で、ルーブリックの再現性を確認する |
| 日記には個人、職場、第三者に関するセンシティブな内容が入りうる | 高 | 保存のオン・オフ、保存範囲、削除、利用目的を保存前に設計する |
| 顧客や身近な人の詳細な人物データを保存すると、本人の知らないところで第三者情報が蓄積される | 高 | 必要最小限の特徴だけを保存し、実名や連絡先を持たない初期仕様を検討する |
| AI ペルソナの反応を「実在人物もこう反応する」と受け取る可能性がある | 高 | 予測ではなく練習用の反応例であると明示し、複数の反応を提示する |
| AI 生徒が高得点することを、実在生徒の理解を保証する根拠にしてしまう | 高 | シミュレーションと実学習効果を区別し、実生徒への小テストや教え返しを代替しない |
| プレゼンの「信頼度」を印象で採点すると、自信のある誤答を高く評価する恐れがある | 高 | 正確性、根拠、不確実性の扱い、一貫性を分離して採点する |
| 「厳しい上司」が必要以上に攻撃的だと、学習効果よりストレスが勝る | 中 | 厳しさを「攻撃性」でなく「待つ時間」「不足を自分から聞く度合い」「深掘りの少なさ」で設計する |

## お客様・関係者と詰めるべき事項

| 確認相手 | 確認内容 | 回答が決定にどう効くか |
|---|---|---|
| プロダクトオーナー | 面接に限定するか、「伝える力」全般へ広げるか | ターゲット、ホーム画面、データモデル、ブランドの再設計範囲が決まる |
| 想定ユーザー | 最も練習したいのは面接、上司報告、表現力、日常会話のどれか | 最初のコースと初期課題を選べる |
| 音声・AI 担当 | 強調と滑舌について、単語区間とピッチ・音量・長さを信頼できる精度で評価できるか | 自動採点の提供時期と技術選定が決まる |
| チーム | 日々の出来事、評価履歴、音声のどれを保存するか | プライバシー、削除、学習の継続性の仕様が決まる |
| チーム | 実在人物に似たペルソナの保存をどこまで認め、匿名と識別情報をどう扱うか | ペルソナ入力項目、利用規約、保存・削除仕様が決まる |
| 教育関係者 | AI 生徒の理解モデルが、授業改善の気づきとして有用か | 先生向けコースの評価表現と、実生徒による検証の必要性が決まる |
