# 検討: Node.js バージョンの選定と固定方法

- ステータス: 結論
- 開始日: 2026-08-06
- 最終更新: 2026-08-06
- 関連: [ADR-0001](../ADR/0001-フロントエンド実行環境.md)(フォローアップ「Node バージョンを Vercel と統一する」に対応)、[タスクメモ: 0805-Frontend動作検証用初期構築](../task-memo/0805-Frontend動作検証用初期構築.md)、[検討: Docker 開発用ベースイメージ](20260806_フロントエンド開発用Dockerベースイメージ.md)(本検討の結果を使う)

## 背景・きっかけ

ADR-0001 でフロントエンドの本番デプロイ先は Vercel に決定し、ローカル開発は Docker 上で `next dev` を実行する方針となった。その際「ローカルと Vercel で Node バージョンを統一する」ことがフォローアップとして残っている。

`frontend/` に Next.js プロジェクトを作成する前に、使用する Node.js のメジャーバージョンと、それをどこで固定するかを決める必要がある。

## 論点

1. **Node.js のメジャーバージョンをいくつにするか**(Vercel がサポートする範囲から選ぶ)
2. **バージョンをどのファイルで固定するか**(`.nvmrc` / `package.json` の `engines` / Dockerfile)

## 事実確認(出典付き)

**Vercel 側の制約:**

- Vercel が使える Node.js は **24.x(デフォルト)/ 22.x / 20.x** のメジャー3系のみ。新規プロジェクトは「Vercel で利用可能な最新の LTS」がデフォルトになる。マイナー・パッチは Vercel 側が自動更新する(出典: [Vercel Docs: Supported Node.js versions](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)、ページ更新日 2026-02-27)
- バージョンを指定する方法は **Project Settings のドロップダウン** と **`package.json` の `engines.node`** の2つ。`engines.node` は Project Settings を上書きする。**`.nvmrc` については同ドキュメントに記載がない**(出典: 同上)
- `engines.node` に `24.x` / `^24.0.0` / `>=20.0.0` のいずれかを書くと、最新の 24.x にデプロイされる(出典: 同上)

**Next.js 側の要件:**

- Next.js 16.3 の動作要件は **Node.js 20.9 以上**(出典: [Next.js Docs: Installation](https://nextjs.org/docs/app/getting-started/installation)、ページ更新日 2026-07-21)

**Node.js 本体のサポート期限:**

- **Node 20: 2026-04-30 に EOL 済み**(本検討時点で既にサポート終了)
- Node 22: 2025-10-21 に Active LTS 終了、メンテナンス期間は 2027-04-30 まで
- Node 24: Active LTS(2026-10-20 まで)、セキュリティサポートは 2028-04-30 まで
- (出典: [endoflife.date/nodejs](https://endoflife.date/nodejs))

## 選択肢の比較

### 論点1: メジャーバージョン

比較軸: **Vercel との整合**(ADR-0001 のフォローアップ)、**サポート期間**、**設定漏れへの耐性**。

| 観点 | A案: 20.x | B案: 22.x | **C案: 24.x** |
|---|---|---|---|
| Node.js 公式サポート | **2026-04-30 に EOL 済み** | メンテナンスのみ(2027-04-30 まで) | **Active LTS**(2028-04-30 まで) |
| Vercel サポート | あり | あり | **あり(デフォルト)** |
| Next.js 16.3 の要件(20.9+) | 満たす | 満たす | 満たす |
| Vercel 側の設定漏れ耐性 | 明示指定が必須 | 明示指定が必須 | **デフォルトと一致するため取り違えが起きにくい** |
| Docker イメージ | `node:20-*` | `node:22-*` | `node:24-*` |

**推奨: C案 24.x。** Node 20 は既に EOL、Node 22 も Active LTS を終えている。Vercel のデフォルトも 24.x のため、ローカル・Vercel 双方で最も揃えやすく、Project Settings を触り忘れても意図しないバージョンにならない。

### 論点2: 固定方法

| 方法 | Vercel に効くか | ローカル(Docker)に効くか | 備考 |
|---|---|---|---|
| `package.json` の `engines.node: "24.x"` | **効く**(Project Settings を上書き) | 効かない(宣言のみ) | Vercel 公式ドキュメントに記載のある方法 |
| Vercel Project Settings | 効く | 効かない | GUI 操作のためコードに残らない |
| `.nvmrc` | **公式ドキュメントに記載なし**(効くと期待しない) | 効かない(ホストの nvm 用) | ホストで直接動かす人向けの補助 |
| Dockerfile の `FROM node:24-*` | 効かない | **効く** | ローカルの実体を決めるのはこれ |

**推奨: `engines.node` を「正」とし、Dockerfile のイメージタグを一致させる。** タスクメモには「`.nvmrc`(または `package.json` の `engines`)で固定する」と書かれていたが、Vercel との整合を担保できるのは `engines` のみ。`.nvmrc` はホストで直接 `next dev` を動かす人のための補助として置くのは構わないが、Vercel 側の根拠にはしない。

## 懸念

| 懸念 | 深刻度の感触 | 解消に必要な確認 |
|---|---|---|
| `.nvmrc` を Vercel との整合の根拠にすると、Vercel 側が別バージョン(Project Settings のデフォルト)でビルドされ、「ローカルでは動くのに Vercel で落ちる」が起こる | 中 | `package.json` の `engines.node` を必ず設定する。初回デプロイ後に Vercel のビルドログで実際の Node バージョンを確認する |
| Node 24 の Active LTS は 2026-10-20 まで。それ以降は Node 26 が最新 LTS となり、Vercel のデフォルトも移る見込み | 低(ハッカソン期間中は影響なし) | 長期運用するなら、Vercel のサポートバージョン更新に追随する運用を決める |

## お客様・関係者と詰めるべき事項

特になし。事実(Vercel のサポート範囲・Node の EOL)からほぼ一意に決まる論点のため、チーム内の承認のみで足りる。

## 議論ログ

- **2026-08-06 ラウンド1**: Vercel 公式ドキュメント・Next.js 公式ドキュメント・endoflife.date を一次情報として調査。Node 20 が既に EOL であること、Vercel のデフォルトが 24.x であることから 24.x を推奨。あわせて **Vercel 公式ドキュメントに `.nvmrc` の記載がない**ことが判明したため、タスクメモの「`.nvmrc`(または `engines`)」という記述を `engines` 主体に改めるべきと整理した。ユーザーの最終決定待ち。

## 結論

**推奨案**:

| 項目 | 推奨 |
|---|---|
| Node.js メジャーバージョン | **24.x** |
| 固定方法(正) | `package.json` の `engines.node: "24.x"` |
| 固定方法(ローカル実体) | Dockerfile の `FROM node:24-*` を一致させる |
| `.nvmrc` | 置いてもよいが Vercel 向けの根拠にはしない(任意) |
