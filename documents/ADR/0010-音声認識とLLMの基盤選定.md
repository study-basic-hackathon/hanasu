# ADR-0010: 文字起こしに AmiVoice、会話・評価の LLM に Bedrock を使う

- ステータス: 決定
- 日付: 2026-08-16
- 依存: [ADR-0009](0009-評価方式.md)（フィラーの数を評価指標に含める）

## コンテキスト(背景と課題)

[技術スタック.md](../技術スタック.md) では音声認識が `open whisper？` と**疑問符付き**で記載され、未確定だった。LLM は Bedrock を利用する想定で [#28 Bedrock連携基盤の構築](https://github.com/study-basic-hackathon/hanasu/issues/28) が起票済み。

[ADR-0009](0009-評価方式.md) で**フィラーの数を評価指標に含める**ことが決まったため、「フィラーを落とさずに文字起こしできるか」が音声認識サービスの選定を左右することになった。一般的な STT はフィラーを**自動で除去する**ため、この要件は選定の決め手になる。

外部の有償 API を使ってよいかはチームに確認し、**使用可能**との回答を得た（2026-08-16）。

## 決定

- **文字起こし（STT）には AmiVoice を使う。** リクエストに **`keepFillerToken=1`** を必ず付与する。
- **会話・評価の LLM には Amazon Bedrock を使う。**
- **TTS で使用するサービスは未定とする**（TTS 自体が任意のため、作ると決めた時点で選ぶ）。

## 検討した選択肢

- STT
  - AmiVoice（**採用**）
  - Whisper（ECS 上でセルフホスト）
  - Amazon Transcribe
  - OpenAI の Whisper / GPT-Transcribe 系
- LLM
  - Amazon Bedrock（**採用**）
  - 外部 API（Claude / GPT の chat API）

## 決定要因

- **フィラーを保持したまま文字起こしできるか**（[ADR-0009](0009-評価方式.md) の要件）
- ECS のリソース制約（CPU 256 / メモリ 512MB）
- [技術スタック.md](../技術スタック.md) の想定との整合
- 外部有償 API の利用可否（チーム確認済み: 使用可能）

## 理由

- **AmiVoice を採用**: `keepFillerToken=1` を指定するとフィラーの自動除去が無効化され、**フィラー単語が半角 `%` で囲まれて返る**（例: `%えー%`）。**正規表現で数えるだけでフィラー計測が完了する**ため、自前でフィラー辞書を作るより精度・工数ともに有利。課金は発話区間のみが対象で、間の多い練習音声と相性が良い。
- **Whisper のセルフホストを見送り**: 現在の ECS タスクは CPU 256 / メモリ 512MB で、**モデルを載せるには足りない**見込み。タスク定義の増強が必要になる。またフィラーを自動除去する。
- **Amazon Transcribe を見送り**: **`keepFillerToken` に相当する機能がない。** フィラー計測が中核である以上、寄せられない。
- **Bedrock を採用**: [技術スタック.md](../技術スタック.md) の想定に沿い、AWS 内で完結する。外部 API も使用可能になったが、**AWS に寄せることでキー管理の対象を増やさずに済む**。
- **TTS を未定のまま残す**: [ADR-0008](0008-会話用APIの構成.md) のとおり **TTS 自体が任意**であり、作ると決めた時点で選べばよい。

## 影響・トレードオフ

- 良い影響:
  - **フィラー計測が正規表現だけで済む**（AmiVoice がトークンを付けて返すため）
  - ECS 上で重い音声処理を回さずに済み、**タスク定義の増強が不要**
  - LLM が AWS 内で完結し、[技術スタック.md](../技術スタック.md) の想定と整合する
- 受け入れたトレードオフ・残るリスク:
  - **Bedrock をアプリから呼ぶには ECS タスクロールの新設が必要。** 現状の実行ロール（`ecs_task_execution`）は ECR pull とログ出力用で、`bedrock:InvokeModel` には使えない（`infra/dev/ecs.tf` / `infra/dev/iam.tf`）。**[#28 Bedrock連携基盤](https://github.com/study-basic-hackathon/hanasu/issues/28) が会話機能のブロッカーになる**
  - **AmiVoice は商用の外部 API** であり、アカウント・課金・API キーの管理が必要
  - **`keepFillerToken=1` が期待どおり効くかは実装して確かめる必要がある。** ここが崩れるとフィラー計測の実現方法から再検討になる

## フォローアップ

- **[#28 Bedrock連携基盤](https://github.com/study-basic-hackathon/hanasu/issues/28) に ECS タスクロールの新設が含まれるか確認する**（担当: TAKUO2000）
- `backend/pyproject.toml` に `boto3` を追加し、Bedrock のモデルを選定する
- **AmiVoice の API キーの管理方法を決める。** 既存実装は `JWT_SECRET_KEY` を環境変数で受けている（`backend/app/security.py`）ため、同じ形に揃えるのが素直
- **`POST /interviews/stt` を最初に実装し、フィラーが `%` 付きで返ることを単体で検証する**（ここが崩れると後続がすべて空振りになる）
- TTS を実装する場合のサービスを選ぶ。**Bedrock 採用で ECS タスクロールが新設されるため、Amazon Polly なら `polly:SynthesizeSpeech` を足すだけで済む**
- [技術スタック.md](../技術スタック.md) の音声認識の記載（`open whisper？`）を更新する
- 再検討のトリガー: **`keepFillerToken` が期待どおり動かない**場合、**外部有償 API が使えなくなった**場合
