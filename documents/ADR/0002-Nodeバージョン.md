# ADR-0002: Node.js のバージョンを 24.x とし `package.json` の `engines` で固定する

- ステータス: 決定
- 日付: 2026-08-06
- 依存: **[ADR-0001](0001-フロントエンド実行環境.md)(デプロイ先を Vercel とする)に依存する。** 本 ADR は ADR-0001 のフォローアップ「Node バージョンを Vercel と統一する」を具体化したものであり、「Vercel がサポートするバージョンから選ぶ」「Vercel が読む方法で固定する」という制約は ADR-0001 の決定から導かれている。**ADR-0001 が覆った場合(デプロイ先が Vercel でなくなった場合)は本 ADR も再検討が必要。**

## コンテキスト(背景と課題)

[ADR-0001](0001-フロントエンド実行環境.md) でフロントエンド(Next.js)の本番デプロイ先を Vercel に決定し、ローカル開発は Docker 上で `next dev` を実行する方針とした。本番ビルドが Vercel 側で行われるためローカルとの完全な dev/prod 一致は得られず、その緩和策として「Node バージョンを統一する」ことがフォローアップとして残っていた。

`frontend/` に Next.js プロジェクトを作成するにあたり、次の2点を確定させる必要があった。

1. どのメジャーバージョンを使うか(Vercel は 24.x / 22.x / 20.x のみサポート)
2. そのバージョンをどこで固定するか(ローカルと Vercel の双方に効く方法である必要がある)

なお ADR-0001 のフォローアップには「`.nvmrc` 等で」と記載していたが、調査の結果 **Vercel 公式ドキュメントに `.nvmrc` の記載はなく、Vercel が読むのは Project Settings と `package.json` の `engines.node` のみ**であることが判明した。この前提の誤りを正すことも本 ADR の目的に含む。

## 決定

- フロントエンドで使用する Node.js は **24.x** とする。
- バージョン固定の「正」は **`package.json` の `engines.node: "24.x"`** とし、開発用 Dockerfile のイメージタグ(`node:24-*`)をこれに一致させる。
- **`.nvmrc` は Vercel との整合の根拠にしない。** ホストで直接 `next dev` を動かす人向けの補助として置くことは許容する。

## 検討した選択肢

**メジャーバージョン:**

- A案: 20.x
- B案: 22.x
- C案: 24.x

**固定方法:**

- `package.json` の `engines.node`
- Vercel Project Settings
- `.nvmrc`
- Dockerfile のイメージタグ

## 決定要因

- Vercel との整合(ADR-0001 のフォローアップ)
- Node.js 本体のサポート期間(EOL していないこと)
- 設定漏れ・取り違えへの耐性
- 設定がコードとして残ること

## 理由

- **24.x を採用**: Vercel が使える3系のうち、Node 20 は 2026-04-30 に EOL 済み、Node 22 も 2025-10-21 に Active LTS を終えている。**Active LTS なのは 24.x のみ**(セキュリティサポートは 2028-04-30 まで)。加えて Vercel の新規プロジェクトのデフォルトが 24.x のため、Project Settings を触り忘れてもローカルと食い違わない。
- **20.x を見送り**: 既に EOL でセキュリティ更新を受けられない。
- **22.x を見送り**: 動作はするが Active LTS を終えており、24.x を選ばない積極的な理由がない。
- **`engines.node` を固定方法の正とする**: Vercel 公式ドキュメントに記載のある指定方法であり、Project Settings を上書きできる。GUI 設定と違ってコードとして残り、リポジトリを見れば分かる。
- **`.nvmrc` を正としない**: Vercel 公式ドキュメントに記載がなく、効くと期待できない。これを根拠にすると Vercel 側が Project Settings のデフォルトでビルドされ、「ローカルでは動くのに Vercel で落ちる」を招く。

## 影響・トレードオフ

- 良い影響:
  - ローカル(Docker)と Vercel の Node バージョンが一致し、ADR-0001 で受け入れた dev/prod 不一致のリスクが緩和される
  - Active LTS を選ぶことで、ハッカソン期間を超えて使う場合もセキュリティ更新を受けられる
  - 固定がコード(`package.json` / Dockerfile)に残るため、新しいメンバーが GUI 設定を知らなくても再現できる
- 受け入れたトレードオフ・残るリスク:
  - Node 24 の Active LTS は 2026-10-20 まで。それ以降は Node 26 が最新 LTS となり Vercel のデフォルトも移る見込みだが、ハッカソン期間中は影響しない
  - `engines.node` と Dockerfile のイメージタグは別々の場所にあるため、片方だけ更新するとずれる。更新時は両方を揃える必要がある

## フォローアップ

- `create-next-app` 実行後、`package.json` に `engines.node: "24.x"` を追加する(タスクメモ [0805-Frontend動作検証用初期構築](../task-memo/0805-Frontend動作検証用初期構築.md) フェーズ1)
- 開発用 Dockerfile のベースイメージを `node:24-*` にする(ベースイメージのバリアント選定は別途検討中)
- Vercel への初回デプロイ後、ビルドログで実際に使われた Node バージョンが 24.x であることを確認する
- 再検討のトリガー: Node 24 が Active LTS を終え Vercel のデフォルトが移った場合、または使用ライブラリが Node 24 に非対応と判明した場合
