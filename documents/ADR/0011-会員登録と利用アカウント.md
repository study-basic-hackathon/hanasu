# ADR-0011: 会員登録を実装せず、固定の ID / パスワード1組で利用する

- ステータス: 決定
- 日付: 2026-08-16
- 被依存: [#27](https://github.com/study-basic-hackathon/hanasu/issues/27) 画面一覧（会員登録画面の要否）、[#2](https://github.com/study-basic-hackathon/hanasu/issues/2) ログイン画面、[#17](https://github.com/study-basic-hackathon/hanasu/issues/17) 応募企業情報の項目定義（1ユーザー前提）

## コンテキスト(背景と課題)

ハッカソン期間内に**本番モード（AI 面接官との模擬面接）を作り上げること**が最優先である。

認証は既に実装済みで、`POST /token` が JWT アクセストークンを返し、保護 API は `Depends(get_current_user)` で守る形が確立している（[#7](https://github.com/study-basic-hackathon/hanasu/issues/7) 完了）。一方で**会員登録（サインアップ）の API と画面は未実装**であり、[必要api .md](../必要api.md) にも会員登録 API は存在しない。

[技術スタック.md](../技術スタック.md) では既に **Amazon Cognito を使わず「認証は簡易的」**とする方針が示されていたが、**会員登録そのものを作るかどうかは決まっていなかった。**

## 決定

- **会員登録を実装しない。** サインアップの API・画面とも作らない。
- **固定の ID / パスワード1組**でログインする。
- **ユーザーは1つだけ**とする。応募企業情報・評価履歴はすべてこの1ユーザーに紐づく。

2026-08-16 のチーム会議で決定した。

## 検討した選択肢

- A案: 会員登録を実装する（サインアップ API + 画面 + 重複チェック）
- B案: 会員登録を実装せず、固定の ID / パスワード1組で利用する（**採用**）
- C案: 認証自体をなくす

## 決定要因

- **期間内に本番モードを完成させられるか**（最優先事項）
- 実装済みの JWT 認証（[#7](https://github.com/study-basic-hackathon/hanasu/issues/7)）をそのまま活かせるか
- [必要api .md](../必要api.md) の API 制約「**認証ユーザーのみ実行可能**」を満たせるか

## 理由

- **B案を採用**: 認証 API は既に動いており、**固定アカウントであればユーザー管理の実装が一切要らない**。それでいて全 API に JWT を課す制約はそのまま満たせる。
- **A案を見送り**: サインアップ API・登録画面・メール重複チェック・パスワードのハッシュ化と再設定など、**本番モードの完成に寄与しない実装が積み上がる**。
- **C案を見送り**: [必要api .md](../必要api.md) の「認証ユーザーのみ実行可能」を崩すことになり、**実装済みの JWT 認証を外す手戻り**が生じる。

## 影響・トレードオフ

- 良い影響:
  - **会員登録画面とサインアップ API が不要**になる（[#27](https://github.com/study-basic-hackathon/hanasu/issues/27) の画面一覧から会員登録が外れる）
  - **パスワード再設定も不要**になる
  - ユーザーが1つのため、応募企業情報とユーザーの紐付けを単純化できる
- 受け入れたトレードオフ・残るリスク:
  - **複数人が同時にデモすると、同じアカウントのデータを共有する。** 応募企業情報・評価履歴が混ざる
  - **サービスとして継続する場合は会員登録の実装が必要**で、その時点で応募企業情報・評価履歴を `user_id` に紐付け直すことになる
  - **「初回サインアップ時のみ表示する」という初回判定の考え方が使えない。** 画面の出し分けは別の条件（応募企業情報が登録済みかなど）で行う必要がある

## フォローアップ

- **固定の ID / パスワードの管理方法を決める。** 既存実装は `JWT_SECRET_KEY` を環境変数で受けている（`backend/app/security.py`）ため、同じ形に揃えるのが素直
- [#27](https://github.com/study-basic-hackathon/hanasu/issues/27) の画面一覧から**会員登録の要素を外す**（S-01 が「サインイン / 会員登録」になっている）
- [#17](https://github.com/study-basic-hackathon/hanasu/issues/17) で、**登録データが1ユーザー分しか存在しない前提**を反映する
- 再検討のトリガー: **ハッカソン後にサービスとして継続する**場合、または**複数人が同時に利用するデモが必要になった**場合

## 備考

同じ会議で、**練習モードは画面モックのみ作る**こと、**チュートリアルは本番モードの画面・API を流用して自己紹介1問だけを出題する形に変える**ことも決まっている。あわせて、**プロフィールを独立した画面として持たず応募企業情報の登録に集約する**こと、**過去の評価結果を一覧で見る画面を今回作る**ことも確認された。いずれも実装スコープの決定であり、[ユースケース・ユーザーフロー.md](../ユースケース・ユーザーフロー.md) の 2.2 に記載した。
