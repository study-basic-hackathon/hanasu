# ADR-0003: フロントエンドのパッケージマネージャを npm とする

- ステータス: 決定
- 日付: 2026-08-06
- 依存: **[ADR-0001](0001-フロントエンド実行環境.md)(デプロイ先を Vercel とする)に依存する。** Vercel が lockfile からパッケージマネージャを自動検出するという制約が、本 ADR の判断軸(追加設定なしで Vercel と整合するか)を規定している。ADR-0001 が覆った場合は本 ADR も再検討が必要。
- 被依存: **[ADR-0004](0004-Nextjsプロジェクト初期構成.md)** が本 ADR に依存する(`create-next-app` の `--use-npm` 指定)。

## コンテキスト(背景と課題)

`frontend/` に Next.js プロジェクトを作成するにあたり、パッケージマネージャを確定させる必要があった。この決定は次の3か所に影響する。

- **Vercel のビルド**: lockfile の種類からパッケージマネージャが自動検出される
- **Docker 開発環境**: `node_modules` をコンテナ側の named volume に分離する構成での挙動
- **`create-next-app` の実行**: 生成時に lockfile の種類が決まり、後から変えるには依存の入れ直しが必要

候補は npm と pnpm の2つだった。

## 決定

フロントエンドのパッケージマネージャは **npm** とする。

- `package-lock.json` を必ずコミットし、Vercel には lockfile 検出に任せる
- Vercel Project Settings の Override(`installCommand`)は使わない

## 検討した選択肢

- A案: npm
- B案: pnpm

## 決定要因

- Vercel との整合(追加設定なしで意図したバージョンが使われるか)
- Docker / Dev Container での構築の手間
- 性能面の利点(インストール速度・ディスク使用量)が今回の規模で効くか

## 理由

- **npm を採用**: node 公式イメージに同梱されているため Docker 側の準備が不要で、Vercel も `package-lock.json` を検出して npm 10 を使う。**両方で追加設定がゼロになる**。`node_modules` をフラットに展開するため、named volume に分離する構成でも素直に動く。
- **pnpm を見送り**: インストール速度と省ディスクで優位だが、その恩恵は依存の重複が多い複数プロジェクト環境で大きく、単一プロジェクトの本リポジトリでは効きにくい。加えて Docker 側で `corepack enable` のセットアップが1手増え、Vercel 側も `lockfileVersion: 9.0` では pnpm 9 と 10 のどちらが使われるかビルドログを見ないと分からない。シンボリックリンク + `.pnpm` ストア構造と named volume 分離の組み合わせも動作確認が必要な未知数になる。フェーズ2 の Dev Container 化まで進める工程で、ハマりどころを増やさない判断を優先した。

## 影響・トレードオフ

- 良い影響:
  - Vercel・Docker のどちらにも追加設定が不要で、環境構築が最短になる
  - `create-next-app` を `npx` で実行すればそのまま npm 構成になり、生成手順がシンプルになる
- 受け入れたトレードオフ・残るリスク:
  - pnpm と比べてインストールが遅く、ディスク使用量も多い(単一プロジェクトのため影響は限定的)
  - 将来 `backend/` `frontend/` をモノレポとして扱う場合、pnpm workspaces のほうが有利だったと判明する可能性がある
  - `package-lock.json` をコミットし忘れると、Vercel が lockfile なしと判断して意図しない依存解決になる

## フォローアップ

- `create-next-app` を `--use-npm` 付きで実行する(タスクメモ [0805-Frontend動作検証用初期構築](../task-memo/0805-Frontend動作検証用初期構築.md) フェーズ1)
- `package-lock.json` を `.gitignore` に入れず、必ずコミットする
- 再検討のトリガー: `backend/` を含むモノレポ構成に移行する場合、または依存インストール時間が開発の障害になった場合
