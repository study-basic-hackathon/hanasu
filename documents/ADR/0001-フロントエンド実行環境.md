# ADR-0001: フロントエンドのデプロイ先を Vercel とする

- ステータス: 決定
- 日付: 2026-08-05
- 被依存: **本 ADR にはフロントエンド初期構築の各 ADR が依存する。本 ADR が覆る(デプロイ先が Vercel でなくなる)場合は、以下もすべて再検討が必要。**
  - [ADR-0002](0002-Nodeバージョン.md)(Node.js を 24.x とし `engines` で固定する) — 本 ADR のフォローアップ「Node バージョンを Vercel と統一する」を具体化
  - [ADR-0003](0003-パッケージマネージャ.md)(パッケージマネージャを npm とする) — Vercel の lockfile 検出が判断軸
  - [ADR-0004](0004-Nextjsプロジェクト初期構成.md)(Next.js プロジェクトの初期構成) — Vercel でのビルドが前提
  - [ADR-0005](0005-開発バンドラ.md)(開発バンドラを Turbopack とする) — 本番ビルドが Vercel 側であることが前提
  - [ADR-0006](0006-開発用Dockerベースイメージ.md)(開発用 Docker ベースイメージ) — 開発専用イメージであることが前提

## コンテキスト(背景と課題)

hanasu のフロントエンド(TypeScript / Next.js、`frontend/` に配置予定)の本番実行環境を決める必要があった。ローカル開発は Docker 上で行う方針。バックエンド(Go)を AWS ECS で動かす想定のため、フロントも AWS(ECS / Amplify)に置く案が浮上したが、既存の `documents/技術スタック.md` には「デプロイ先: Vercel」と記載されており、3案を比較して決着させることにした。ハッカソンの期間内に確実に動かすことが前提。

## 決定

フロントエンド(Next.js)の本番デプロイ先は **Vercel** とする。ローカル開発は方針どおり Docker 上で `next dev` を実行する。

## 検討した選択肢

- A案: ECS (Fargate)
- B案: Amplify Hosting
- C案: Vercel

## 決定要因

- コスト(検討時の重視軸)
- 構築の速さ・簡単さ(ハッカソン期間内に確実に動かす)
- Next.js との相性
- ローカル Docker 開発との整合
- 既存ドキュメント(技術スタック.md)との整合

## 理由

- **C案 Vercel を採用**: Git 連携のみでデプロイでき構築の手間が3案中最小。Next.js との相性も最良。「Vercel を使って簡単にデプロイする」というチーム方針に合致し、既存ドキュメントの記載とも整合する。
- **A案 ECS を見送り**: 月 $25〜40 程度の常時課金(Fargate + ALB + ECR)に加え、Dockerfile / ECR / ALB / パイプラインの構築の手間がハッカソン期間には重い。
- **B案 Amplify を見送り**: コスト軸では無料枠内でほぼ $0 と最優位だったが、デプロイの簡単さとチーム方針を優先して Vercel とした。

## 影響・トレードオフ

- 良い影響:
  - デプロイ環境の構築に時間を使わず、本体機能(音声分析・評価)に注力できる
  - Git 連携により CI/CD(プレビューデプロイ含む)が自動で手に入る
  - 技術スタック.md の記載どおりのためドキュメント修正が不要
- 受け入れたトレードオフ・残るリスク:
  - Vercel Hobby プランは個人・非商用利用限定。会社ドメインでの利用が規約に収まるかは未確認(抵触時は Pro $20/ユーザー/月)
  - 本番がコンテナ実行でないため、ローカル Docker との完全な dev/prod 一致は得られない(Node バージョンの統一で緩和)
  - フロントのみ AWS 外となり、バックエンド(ECS)とプラットフォーム管理が分かれる

## フォローアップ

- `frontend/` に Next.js プロジェクトと Docker 開発環境をセットアップする(Node バージョンを Vercel と統一)
  - Node バージョンの統一方法は **[ADR-0002](0002-Nodeバージョン.md) で決定済み**(2026-08-06)。なお本 ADR に記載した「`.nvmrc` 等で」は誤りで、Vercel に効くのは `engines.node` と Project Settings のみであることが ADR-0002 の検討過程で判明した
- Vercel のアカウント/チーム設定と Git リポジトリ連携を行う
- フロントエンド仕様書にこの決定を反映する
- 再検討のトリガー: Vercel Hobby の非商用制約に抵触すると判明した場合(Pro 化または B案 Amplify を再検討)、またはフロントも AWS 内完結が要件になった場合
