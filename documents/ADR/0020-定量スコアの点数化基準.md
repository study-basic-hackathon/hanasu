# ADR-0020: 定量スコアの点数化と総合スコアの合成基準を固定する

- ステータス: 決定
- 日付: 2026-08-28
- 依存: [ADR-0009](0009-評価方式.md)（定量はクライアント、定性は LLM で評価する）
- 被依存: [Issue #57](https://github.com/study-basic-hackathon/hanasu/issues/57) がブロックする定量スコア実装

## コンテキスト（背景と課題）

ADR-0009 は、話速とフィラーをクライアントが点数化すると決めたが、実測値を0〜100点へ変換する基準をフォローアップとして残していた。暫定実装には、画面仕様の適正域を使った話速の減点と、フィラーを1回答あたりへ切り替える欠測時処理がある。正式な基準点、丸め、文字入力・欠測回答、総合スコアの扱いを固定しないと、同じ入力に対する評価を再現できない。また、ADR-0009 内で定量値を LLM に渡すかについて記述が矛盾していたため、定量・定性の入力境界も一意にする必要がある。

## 決定

- 話速とフィラーは [評価仕様](../評価仕様.md) の基準点間を線形補間し、点数だけを最後に四捨五入した0〜100の整数とする。
- 指標に必要な値を計測できた音声回答だけを合算する。文字入力と欠測回答は除外し、対象回答がなければその項目のスコアを作らない。
- フィラーは常に1分あたりの平均回数で評価し、「1回答あたり」のフォールバックは採用しない。
- 総合スコアはバックエンドが、話速・フィラー・構成内容のうち存在する項目を同じ重みで平均して四捨五入する。任意の「間の長さ」は含めない。
- LLM には会話内容だけを渡し、定量の実測値・スコアは渡さない。
- 計算規則の正本は [評価仕様](../評価仕様.md) とし、本 ADR は選択理由を記録する。

## 検討した選択肢

- 線形補間の入力
  - 丸め前の実測値を使い、点数だけを四捨五入する（採用）
  - 話速を整数、フィラーを小数第1位に丸めてから補間する
- 時間欠測・文字入力混在時
  - 計測できた音声回答だけを毎分基準で評価する（採用）
  - セッション全体を「1回答あたり」の基準へ切り替える
  - 欠測が1件でもあれば定量スコアを作らない
- 総合スコア
  - 存在する基本3項目を等価平均する（採用）
  - 基本3項目がすべて揃った場合だけ平均する
  - 任意項目を含め、`scores` に存在する全項目を平均する
- LLM の入力
  - 会話内容だけを渡し、定量の実測値・スコアは渡さない（採用）
  - 点数は渡さず、定量の実測値を助言用に渡す
- 仕様の正本
  - 全体共通の評価仕様を作る（採用）
  - ADR または画面仕様だけに計算規則を置く

## 決定要因

- 同じ実測値から同じ点数を再現できること
- 評価尺度を入力方式や欠測の有無で変えないこと
- 文字入力や一部欠測があっても、計測できた音声を評価できること
- 任意指標の実装有無で総合スコアの意味を変えないこと
- 仕様、決定理由、検討経緯の正本を分離するドキュメント規約との整合

## 理由

- **丸め前の実測値を採用:** 中間丸めによる境界付近の点数差を避け、「最終的な点数を四捨五入する」という基準に揃えられる。
- **計測できた音声だけを採用:** 文字入力や欠測回答を分母へ含めず、取得できた音声の実測値をそのまま評価できる。「1回答あたり」へ切り替える案は、毎分基準と異なる尺度になるため見送った。
- **存在する基本項目の等価平均を採用:** 文字入力だけの場合などでも総合スコアを表示できる。3項目必須は総合スコアが欠ける結果を増やし、全項目平均は任意の「間」を実装した結果だけ意味が変わるため見送った。
- **定量値を LLM に渡さない:** 定量の評価と LLM による定性評価の入力を分離し、既存の API 仕様どおり LLM の入力を会話内容だけに限定できる。実測値を助言へ使う案は、入力構築とプロンプトの後続実装を増やし、助言の再現性にも影響しうるため見送った。
- **全体共通の評価仕様を採用:** 点数化はクライアント、API、結果画面のすべてに関係する。ADR や画面仕様だけを正本にすると、仕様と決定理由の役割が混ざる。

## 影響・トレードオフ

- 良い影響:
  - 話速・フィラー・総合スコアの境界、丸め、欠測時処理をテスト可能な形で固定できる
  - 文字入力や欠測回答を除外しても、計測できた音声回答を評価に使える
  - 任意指標の追加で総合スコアの意味が変わらない
  - 定量スコアが LLM の定性評価へ混入せず、責務と入力契約が明確になる
- 受け入れたトレードオフ・残るリスク:
  - 計測できた回答だけを使うため、同じ総合点でも元になった項目数や音声回答数が異なる場合がある
  - 対象音声がなければ話速またはフィラースコアが存在しない
  - 現行の暫定実装は中間丸め、1回答あたりフォールバック、全 `scores` 項目の平均を行うため、後続実装で変更が必要になる
  - 過去の音声・文字起こしを保存していないため、保存済み評価を新基準で再計算できない

## フォローアップ

- Issue #57 がブロックする後続実装 Issue で、フロントエンドの点数化・欠測処理とバックエンドの総合スコア算出を [評価仕様](../評価仕様.md) に合わせる。
- 実装時に、基準点、補間区間、0.5の丸め、対象回答の抽出、項目欠測、任意の `pause` 除外をテストする。
- 「間の長さ」を実装する場合は点数化基準を別途決める。総合スコアへ含める場合は本 ADR を再検討する。
