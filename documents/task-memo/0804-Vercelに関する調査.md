# 作業ログ

- Next.js の開発元である Vercel 社が提供するフロントエンド向けのホスティングプラットフォーム(PaaS)

### 特徴
- Git 連携による自動デプロイ: 
  GitHub リポジトリを接続すると、push するだけで自動的にビルド&デプロイされます。CI/CD を自分で組む必要がありません。
- プレビューデプロイ: 
  PR やブランチごとに一意の URL が自動発行されます。「この画面できたよ」とチームに共有するのに便利で、ハッカソンと相性が良いです。


## Next.js アプリのデプロイ方法
基本は GitHub 連携で、手順は以下だけです。
1. vercel.com に GitHub アカウントでサインアップ
2. 「Add New Project」→ 対象リポジトリを Import
3. フレームワークとして Next.js が自動検出される
4. 「Deploy」を押すと初回デプロイ完了。以降は push のたびに自動デプロイ

## 主な設定項目
- 環境変数: ダッシュボードの Settings → Environment Variables で設定
- ビルド設定: Build Command(デフォルト next build)や Node.js バージョンを変更
- vercel.json: リダイレクト・rewrites・ヘッダーなどをコードで管理したい場合にリポジトリに置く設定ファイルです。必須ではありません。
- カスタムドメイン: Settings → Domains から追加できます。ハッカソンならデフォルトの xxx.vercel.app で十分です。

##　補足
- SSR
  Server-Side Rendering / サーバーサイドレンダリング
  リクエストが来るたびに、サーバー側で HTML を生成して返す方式
- API Routes
  Next.js プロジェクトの中に API エンドポイント(サーバー側の処理)を書ける機能
    - 例えば app/api/hello/route.ts にコードを置くと、https://自分のドメイン/api/hello という API になります
    - フロントエンドのリポジトリだけで簡単なバックエンド処理(外部 API の中継、フォーム受付など)が完結します
    - Vercel にデプロイすると、これらは自動的にサーバーレス関数として動きます

- ISR
  Incremental Static Regeneration / インクリメンタル静的再生成
  - 事前に生成した静的ページを、一定間隔で裏側だけ再生成して更新していく方式
  - 作り置きした HTML を配信しつつ、「60秒ごと」などの設定でバックグラウンドで作り直す。速さと鮮度のいいとこ取り
  - ブログ記事や商品一覧のような「たまに更新されるが、毎回生成するほどではない」ページに向きます
- SSG(静的生成)
  - ビルド時に HTML を作り置きする。表示は最速だが、データを更新するには再ビルドが必要
