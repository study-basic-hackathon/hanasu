## 必要API一覧

会話練習に関する API は [ADR-0008](ADR/0008-会話用APIの構成.md) で確定した。パス名は実装時に確定する。

- 認証API（**実装済み**: `POST /token`）
  - input
    - ID,Password
  - output
    - 認証結果（JWT アクセストークン）
- 企業情報登録CRUD API
  - **実態は「応募情報」**（企業情報 + 志望動機 + 経歴を1レコードで持つ）— [ADR-0009](ADR/0009-評価方式.md)
  - Create
    - inputs
      - 企業情報
    - output
      - 登録結果
  - Read
    - inputs
      - 企業ID
    - output
      - 企業情報
  - **List（一覧取得）**
    - inputs
      - なし
    - output
      - 登録済みの応募情報の一覧（**企業ID付き**）
    - 備考
      - **単体取得（Read）だけでは企業IDを知る手段がない。** モード選択の企業リスト、応募企業情報の一覧画面のいずれもこの API に依存する
      - ユーザーは1つのため、**絞り込みは行わず全件を返す**（[ADR-0011](ADR/0011-会員登録と利用アカウント.md)）
      - **[#11](https://github.com/study-basic-hackathon/hanasu/issues/11) の範囲には含めない**と判断した（実装の割り当ては別途決める）
  - Update
    - inputs
      - 企業ID
      - 更新情報
    - output
      - 更新結果
  - Delete
    - inputs
      - 企業ID
    - output
      - 削除結果
- 最初の質問API（`POST /interviews/start`）**※任意・優先度低**
  - 当面はフロントに固定文字列を持つため、作らなくても成立する
  - inputs
    - 企業ID
    - **質問の強度**（楽々 / 標準 / 厳しめ）
  - output
    - 最初の質問
- 音声文字起こしAPI（`POST /interviews/stt`）**※実装最優先**
  - inputs
    - 入力音声（`multipart/form-data`）
  - output
    - 文字起こし（**フィラートークン付きの生テキスト**と、表示用の整形済みテキスト）
    - フィラーの数
    - 発話時間・文字数・話速（文字/分）
  - 備考
    - **AmiVoice に `keepFillerToken=1` を付与**し、フィラーが `%えー%` の形で返るようにする（[ADR-0010](ADR/0010-音声認識とLLMの基盤選定.md)）
    - **生テキストを捨てない。** 整形すると評価が機能しなくなる
- 会話API（`POST /interviews/chat`）
  - inputs
    - 企業ID
    - **質問の強度**（楽々 / 標準 / 厳しめ）
    - これまでの会話履歴
  - output
    - 次のAIの返答（次の質問）
  - 備考
    - **サーバーは会話状態を持たない**ため、履歴は毎回クライアントから送る（[ADR-0008](ADR/0008-会話用APIの構成.md)）
    - **質問の強度も毎回送る。** 状態を持たない以上、開始時に一度だけ渡すことができない。サーバーは強度を system プロンプトの言い回しに反映する
    - **ストリーミングしない。** 1回の JSON で返す
    - **音声入力とテキスト入力の両方を受ける**（テキスト入力のターンは文字起こしAPIを経由しない）
- 音声化API（`POST /interviews/tts`）**※任意**
  - 作らない場合は、AIの返答を画面に文字表示するだけでよい
  - inputs
    - AIの返答テキスト
  - output
    - 音声化データ（`audio/mpeg`）
- 評価実行API（`POST /evaluations`）
  - **非同期**。評価の実行だけを行い、結果は取得APIで受け取る
  - inputs
    - 企業ID（**チュートリアルでは省略する**）
    - これまでの会話履歴全て
    - **定量評価の結果**（話速・フィラー数。**クライアントが算出したもの**）
  - output
    - 評価結果の保管ID
  - 備考
    - **定量はコード、定性は LLM**（[ADR-0009](ADR/0009-評価方式.md)）。定量スコアは DB に保存するだけで LLM には渡さない
    - **チュートリアル用のサンプル応募情報は用意しない。** チュートリアルは自己紹介1問のみで会話API を経由しないため、**この API が企業IDなしを受け付けられればよい**（評価結果テーブルの企業IDは NULL を許す）
- 評価結果取得API（`GET /evaluations/{評価結果の保管ID}`）
  - inputs
    - 評価結果の保管ID
  - output
    - 処理状態（処理中 / 完了 / 失敗）
    - 評価点数
    - アドバイス
  - 備考
    - 完了するまでクライアントがポーリングする。**失敗を表現しないと永久にポーリングし続ける**
    - **合否の目安は API では返さない。** 当面はクライアントが評価点数から判定する（**基準はハードコード**。正式な決め方は後日定める）
- 評価履歴一覧取得API（`GET /evaluations`）
  - inputs
    - なし
  - output
    - これまでの評価結果の一覧（**評価結果の保管ID付き**）
  - 備考
    - 一覧から評価結果取得APIを呼ぶ導線になる
    - **企業では絞り込まず、全件を返す。** 企業をまたいで上達を振り返るため。**企業IDを持たないチュートリアルの結果も同じ一覧に含まれる**

## 評価する指標

[ADR-0009](ADR/0009-評価方式.md) で確定。

- 話の速さ（文字数 ÷ 発話時間）
- フィラーの数
- 構成・内容（**LLM が評価する定性項目**）
- 間の長さ（**優先度「できたら」**）

**「抑揚」「声の大きさ」は採らない。** 抑揚はピッチ抽出が必要で ECS の負荷が厳しく、良し悪しの判定基準を作ることも難しいため。

## API制約

- 認証ユーザーのみ実行可能（**全 API に JWT Bearer**）。ただし**認証API（`POST /token`）だけは未認証で実行できる**必要がある
- **会員登録APIは作らない。** 固定の ID / パスワード1組を使う（[ADR-0011](ADR/0011-会員登録と利用アカウント.md)）
- **サインアウトAPIは作らない。** トークンの破棄はクライアント側で行う
