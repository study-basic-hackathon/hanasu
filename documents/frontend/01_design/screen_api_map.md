# 画面と API の対応

## 1. 本書の位置づけ

**[画面一覧](screen_list.md) の各画面がどの API を呼ぶかを定める。**

**API そのものの定義は [API仕様.md](../../backend/API仕様.md) が正本である。** 本書は画面の側から API を辿るための対応表であり、API の入出力を二重に持たない。

### 本書で決めないこと

| 決めないこと | 扱う場所 |
|---|---|
| API の定義（入出力・制約） | [API仕様.md](../../backend/API仕様.md) |
| API の実装 | 各 API の実装 Issue（[#36](https://github.com/study-basic-hackathon/hanasu/issues/36) など） |
| 画面の役割・表示情報・遷移 | [画面一覧](screen_list.md) / [画面遷移図](screen_flow.md) / [画面詳細仕様](screens/) |
| 応募企業情報の項目の型・制約 | [API仕様.md](../../backend/API仕様.md) 4章 |
| 共通仕様（未認証時のリダイレクト、エラー表示、ローディング表示、マイク許可の拒否時の挙動） | [共通仕様](screen_common.md) |

## 2. 前提

会話・評価まわりは ADR で確定済みである。**本書はこれらを所与とする。**

| # | 前提 | 出典 |
|---:|---|---|
| 1 | **会員登録は作らない。** 固定の ID / パスワード1組でログインし、ユーザーは1つだけ | [ADR-0011](../../ADR/0011-会員登録と利用アカウント.md) |
| 2 | **プロフィールという独立した登録を持たない。** 応募者自身の情報は応募企業情報に含める | [ユースケース](../../ユースケース・ユーザーフロー.md) 2.2 |
| 3 | **サーバーは会話状態を持たない。** 会話履歴と質問の強度はクライアントが保持し、毎ターン送る | [ADR-0008](../../ADR/0008-会話用APIの構成.md) |
| 4 | **音声はブラウザの MediaRecorder で取得し、ターンごとに送る。** サーバーは処理後に破棄し永続化しない | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) |
| 5 | **定量スコアはクライアントが算出**して評価 API に渡す | [ADR-0009](../../ADR/0009-評価方式.md) / [評価仕様](../../評価仕様.md) |
| 6 | **評価は非同期。** 実行 API は ID だけを返し、取得 API でポーリングする | [ADR-0008](../../ADR/0008-会話用APIの構成.md) |
| 7 | **練習モードは画面のモックのみ作る** | [ユースケース](../../ユースケース・ユーザーフロー.md) 2.2 |
| 8 | **チュートリアルは本番モードの画面を流用し、応募企業情報を使わずに自己紹介1問だけを出す** | 同上 |
| 9 | 全 API に JWT Bearer 認証を課す（`POST /token` を除く） | [API仕様.md](../../backend/API仕様.md) 1. 共通事項 |

## 3. 画面と API の対応表

**実装範囲**は [ユースケース](../../ユースケース・ユーザーフロー.md) 2.2 に、**画面 ID** は [画面一覧](screen_list.md) に対応する。**各 API の入出力は [API仕様.md](../../backend/API仕様.md) を参照すること。**

| 画面ID | 画面名 | 実装範囲 | 契機 | 呼ぶ API |
|---|---|---|---|---|
| S-01 | サインイン | 作る | サインインする | `POST /token` |
| S-03 | チュートリアル | 作る（S-08 を流用） | 画面表示 | （なし。最初の質問は固定文字列） |
| S-03 | | | 回答する（音声） | `POST /interviews/stt` |
| S-03 | | | 終える | `POST /evaluations`（**企業IDなし**）→ `GET /evaluations/{id}` をポーリング |
| S-04 | ホーム | 作る | 画面表示 | `GET /evaluations`（**全件から直近1件と件数を拾う**） |
| S-04 | | | 画面表示 | `GET /companies`（**登録件数の表示に使う**） |
| S-05 | 練習の設定 | 作る | 画面表示 | `GET /companies` |
| S-05 | | | 開始する | （なし。選択内容を S-08 に引き継ぐ） |
| S-06 | 応募企業情報 一覧 | 作る | 画面表示 | `GET /companies` |
| S-06 | | | 削除する | `DELETE /companies/{company_id}` |
| S-07 | 応募企業情報 登録 / 編集 | 作る | 編集で開く | `GET /companies/{company_id}` |
| S-07 | | | 募集要項の要約 | `POST /job-postings/summary` |
| S-07 | | | 保存する | 新規は `POST /companies`、編集は `PUT /companies/{company_id}` |
| S-08 | 本番モード | 作る | 画面表示 | `POST /interviews/start`（**任意**。当面はフロントの固定文字列） |
| S-08 | | | 回答する（音声） | `POST /interviews/stt` → `POST /interviews/chat` |
| S-08 | | | 回答する（文字入力） | `POST /interviews/chat`（**STT を経由しない**） |
| S-08 | | | 面接官の発言を読み上げる | `POST /interviews/tts`（**任意**。作らない場合は「読み上げる」を出さない） |

| S-14 | | | 画面表示（S-16 / S-04 から） | `GET /evaluations/{evaluation_id}`（1回） |

**S-02 / S-15 は欠番のため本表に現れない**（[画面一覧](screen_list.md)）。

### 呼び出しの要点

- **`POST /interviews/chat` には、企業ID・質問の強度・会話履歴を毎ターン送る。** サーバーが会話状態を持たないため
- **`POST /interviews/stt` は毎ターン呼ばれるとは限らない。** 文字入力のターンは STT を経由せず `chat` に直接届く
- **合否の目安は API から返らない。** S-14 が総合スコアから判定する（当面はハードコード）
- **全 API に `Authorization: Bearer <access_token>` を付ける。** トークンが無効なら S-01 へ戻す（挙動の定義は [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) の共通仕様）

## 4. フロントエンドが担う責務

**[ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md)〜[ADR-0009](../../ADR/0009-評価方式.md) の決定により、従来サーバー側に置かれることの多い処理がフロントに移っている。** 画面仕様に直接効くため列挙する。

| # | 責務 | 根拠 | 画面仕様への影響 |
|---:|---|---|---|
| 1 | **会話履歴と質問の強度を保持し、毎リクエストに含める** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | **リロードすると会話が失われる。** 離脱時に確認を出す（[共通仕様](screen_common.md) 7.3） |
| 2 | **音声を IndexedDB に一時保持する** | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) | **面接が終わるまで残し、評価の実行と離脱で消す**（[S-08 の詳細仕様](screens/S-08_本番モード.md) 8.1） |
| 3 | **定量スコア（話速・フィラー数）の点数化** | [ADR-0009](../../ADR/0009-評価方式.md) / [評価仕様](../../評価仕様.md) | 計測できた音声回答だけを集計し、基準点間を線形補間する。計測対象がなければ、その項目を評価 API の `scores` から省略する |
| 4 | **評価完了までのポーリング** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | **3秒間隔・最長5分**。`failed` の表示も定めた（[S-14 の詳細仕様](screens/S-14_評価.md)） |
| 5 | **ターン数の上限管理** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | **8ターン**（[S-08 の詳細仕様](screens/S-08_本番モード.md)） |
| 6 | **最初の質問の固定文字列** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | S-08 / S-03 の初期表示をフロントが持つ |
| 7 | **VAD（無音 2〜3秒）と手動停止ボタンの併用** | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) | **無音3秒で自動停止**（[S-08 の詳細仕様](screens/S-08_本番モード.md)） |
| 8 | **合否の目安の判定** | [API仕様.md](../../backend/API仕様.md) 5.6 | S-14 が総合スコアから判定する。**65 / 45 を境にした3段階。当面はハードコード**（[S-14 の詳細仕様](screens/S-14_評価.md)） |
| 9 | **`job_summary` の最大長検査** | [API仕様.md](../../backend/API仕様.md) 4.2 / [S-07](screens/S-07_応募企業情報_登録編集.md) 5章 | 4,000文字を超える要約は省略せず表示し、上限内に編集されるまで保存させない。要約 API と応募情報 CRUD のバックエンドは最大長を検査しない |

**定量スコアの点数化基準は [評価仕様](../../評価仕様.md) で確定している。**

## 6. 画面のために API に加える項目

**[画面詳細仕様](screens/) が定めた表示項目を、[API仕様.md](../../backend/API仕様.md) の現行の入出力と突き合わせた結果である。** 応募企業情報の入出力は [API仕様.md](../../backend/API仕様.md) 4章で整合済みであり、下表は評価 API に残る追加項目だけを示す。募集要項要約は既存 API へ項目を追加するのではなく、[API仕様.md](../../backend/API仕様.md) 4.5 の `POST /job-postings/summary` を呼ぶ。

| # | 画面 | 加える項目 | 加える先 | 現行 |
|---:|---|---|---|---|
| 1 | S-16 | **対象企業と項目別スコア** | `GET /evaluations` の各行 | `evaluation_id` / `created_at` / `status` / `total_score` のみ |
| 2 | S-14 / S-16 | **対象企業の名前**（登録時の値の写し） | 評価結果 | `company_id` のみ返す。**企業を削除しても名前を出せるようにするため、ID の参照では足りない** |
| 3 | S-14 / S-16 | **質問の強度** | `POST /evaluations` のリクエストと評価結果 | リクエストに含まれない |
| 4 | S-14 | **ターン数** | 同上 | 会話履歴を保存しないため、あとから数えられない |

**3・4 は S-08 から続けて S-14 を開いた場合に限ればクライアントの値で表示できるが、履歴から開いた過去の結果には出せない。** 表示を揃えるため評価結果に保存する。

**次の3つは表示しないと決めたため、API への追加も要らない。**

| 表示しないもの | 決めた場所 |
|---|---|
| 応募情報の作成日時・更新日時 | [S-06 の詳細仕様](screens/S-06_応募企業情報_一覧.md) 3章 |
| フィラーの語ごとの内訳（`えー 6` など） | [S-14 の詳細仕様](screens/S-14_評価.md) 4.3 |
| 前回の結果との差分 | [S-14 の詳細仕様](screens/S-14_評価.md) 4.1 |

**画面が日時を必要とするのは評価結果だけである**（S-14 / S-16 の実施日時）。応募情報 API が返す `created_at` は S-06 / S-07 で表示せず、`updated_at` は追加しない。
