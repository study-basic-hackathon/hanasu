## 3. API 一覧

[必要api .md](<../../必要api .md>) で確定した API を、画面から呼ぶ側の視点で並べ直したもの。**パス名は実装時に確定する**（[ADR-0008](../../ADR/0008-会話用APIの構成.md) フォローアップ）。

| エンドポイント | 役割 | 優先度 | 状態 |
|---|---|---|---|
| `POST /token` | サインイン | — | **実装済** |
| `GET /users/me` | サインイン中のユーザー情報取得 | 低 | **実装済**（[必要api .md](<../../必要api .md>) に記載なし） |
| 応募企業情報 CRUD（Create / Read / Update / Delete） | 応募企業情報の登録・取得・更新・削除 | 高 | 記載済・未実装（[#11](https://github.com/study-basic-hackathon/hanasu/issues/11)） |
| **応募企業情報の一覧取得（List）** | 登録済みの応募情報を全件引く | **高** | **本書の指摘により追加**（[5.2](#52-本書の指摘を受けて反映したもの) #2）。**[#11](https://github.com/study-basic-hackathon/hanasu/issues/11) の範囲外のため実装 Issue が未起票** |
| `POST /interviews/start` | 最初の質問を生成 | 任意（低） | 記載済・未実装 |
| `POST /interviews/stt` | 文字起こし + フィラー数 + 話速 | **最優先** | 記載済・未実装（[#36](https://github.com/study-basic-hackathon/hanasu/issues/36)） |
| `POST /interviews/chat` | 次の質問を生成 | 高 | 記載済・未実装。**入力に質問の強度を追加**（[5.2](#52-本書の指摘を受けて反映したもの) #1） |
| `POST /interviews/tts` | 発言の音声化 | 任意 | 記載済・未実装 |
| `POST /evaluations` | 評価の実行（非同期） | 高 | 記載済・未実装。**企業IDは省略可**（チュートリアル用） |
| `GET /evaluations/{evaluation_id}` | 評価結果の取得（一覧からの詳細表示も兼ねる） | 高 | 記載済・未実装 |
| `GET /evaluations` | 評価履歴の一覧（**全件**） | 中 | **企業IDでの絞り込みを廃止**（[5.2](#52-本書の指摘を受けて反映したもの) #3）・未実装 |

## 5. [必要api .md](<../../必要api .md>) との過不足

### 5.1 前版の指摘のうち、決着したもの

**2026-08-13 版で「不足」として挙げた12件のうち8件は、その後の決定で不要になったか、API として確定した。** 記録として残す。

| 前版の指摘 | 決着 |
|---|---|
| 会員登録 API が定義も実装もない（優先度**高**） | **不要になった。** 会員登録を実装せず固定アカウント1組を使う（[ADR-0011](../../ADR/0011-会員登録と利用アカウント.md)） |
| プロフィール登録 / 取得 / 更新 API がない（3件） | **不要になった。** プロフィールを独立して持たず、応募企業情報に集約する |
| 面接セッション管理 API がない | **確定した。** ただし**セッションを持たない形**になった。会話履歴はクライアントが運び、`POST /interviews/chat` に毎回渡す（[ADR-0008](../../ADR/0008-会話用APIの構成.md)） |
| 評価結果の取得 API がない | **確定した。** `GET /evaluations/{evaluation_id}`。**非同期のためポーリングが要る** |
| 評価履歴の一覧取得 API がない（将来対応） | **確定し、今回作ることになった。** `GET /evaluations`（**全件取得**。[5.2](#52-本書の指摘を受けて反映したもの) #3 で企業IDでの絞り込みを廃止） |
| 練習課題の取得 API / 一問一答の質問取得 API がない | **不要になった。** 練習モードは画面モックのみのため |
| 内容評価 API の入力に質問文・企業情報が要る | **解決した。** `POST /evaluations` が `company_id` と `turns`（会話履歴全体）を受ける |
| 音声認識 API を分割するか | **分割しない形で確定した。** `POST /interviews/stt` が文字起こし・フィラー数・話速をまとめて返す |

### 5.2 本書の指摘を受けて反映したもの

**確定した API を画面の側から辿り直したところ、画面が要求するのに API に口がないものが6件あった。2026-08-16 にすべて決着し、[必要api .md](<../../必要api .md>) に反映済みである。**

| # | 指摘 | 決定 | 反映先 |
|---:|---|---|---|
| 1 | **質問強度（楽々 / 標準 / 厳しめ）を渡す口がなかった。** `POST /interviews/chat` の入力は企業IDと会話履歴のみで、**S-05 で選ばせた強度が API に届かなかった** | **API の入力に加える**（`POST /interviews/chat` と `POST /interviews/start` の両方） | [必要api .md](<../../必要api .md>) 会話API / 最初の質問API |
| 2 | **応募企業情報の一覧取得 API がなかった。** Read は単体取得のみで、**企業IDを知る手段がどこにもなかった** | **List を追加する** | [必要api .md](<../../必要api .md>) 企業情報登録CRUD API |
| 3 | **評価履歴を企業横断で引けなかった** | **企業IDでの絞り込みをやめ、全件を返す**（`GET /evaluations?company_id={id}` → `GET /evaluations`） | [必要api .md](<../../必要api .md>) 評価履歴一覧取得API |
| 4 | **チュートリアルのサンプル応募情報の供給元が未定義だった** | **サンプルは用意しない。** チュートリアルは自己紹介1問のみで会話APIを経由しないため、**評価実行APIが企業IDなしを受け付ければ足りる** | [必要api .md](<../../必要api .md>) 評価実行API |
| 5 | **合否の目安を誰が決めるか未定義だった** | **API では返さない。** 当面はクライアントが評価点数から判定する（**基準はハードコード**。正式な決め方は後日） | [必要api .md](<../../必要api .md>) 評価結果取得API |
| 6 | サインアウト API の要否 | **作らない。** トークンの破棄はクライアント側で行う | [必要api .md](<../../必要api .md>) API制約 |

**#1 の帰結**: サーバーが会話状態を持たないため（[ADR-0008](../../ADR/0008-会話用APIの構成.md)）、**質問の強度も会話履歴と同じく毎ターン送ることになる。** 開始時に一度だけ渡す形は取れない。

**#4 の帰結**: 評価結果テーブルの企業IDが NULL を許すことになる。**チュートリアルの結果は企業に紐づかないまま `GET /evaluations` の一覧に並ぶ。**

### 5.3 定義の見直しが要るもの

| # | 対象 | 論点 |
|---:|---|---|
| 1 | **応募企業情報 CRUD の入出力** | 「企業情報」の中身が未定義のまま。**[ADR-0009](../../ADR/0009-評価方式.md) のテーブル定義では `company_name` / `company_info` / `motivation` / `resume` を持つ**が、S-07 の入力欄との対応は [#17](https://github.com/study-basic-hackathon/hanasu/issues/17) で確定させる必要がある |
| 2 | **`GET /users/me` が [必要api .md](<../../必要api .md>) に載っていない** | 実装済みだが一覧にない。**固定アカウント1組のため画面で使う場面はほぼないが、記載は揃えたい** |
| 3 | **`POST /evaluations` の `scores` のキー** | 例示は `speaking_speed` / `filler` のみ。**「間の長さ」を加える場合のキー名**と、画面の項目別スコア表示との対応が未定 |
| 4 | **評価結果の `status` に対する画面の挙動** | `processing` / `completed` / `failed` の3状態がある。**`failed` のときに S-14 が何を表示するか**は [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) の共通仕様で定める |

### 5.4 API 制約

[必要api .md](<../../必要api .md>) は「認証ユーザーのみ実行可能（全 API に JWT Bearer）」とする。**会員登録を作らないことになったため、前版で指摘した「サインイン・会員登録は未認証で実行できる必要がある」という例外は、サインインのみに縮小した。**

| API | 認証 |
|---|---|
| `POST /token` サインイン | **不要**（未認証で実行できる） |
| 上記以外のすべて | 必要 |

## 6. フロントエンドが担う責務

**[ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md)〜[ADR-0009](../../ADR/0009-評価方式.md) の決定により、従来サーバー側に置かれることの多い処理がフロントに移っている。** 画面仕様に直接効くため列挙する。

| # | 責務 | 根拠 | 画面仕様への影響 |
|---:|---|---|---|
| 1 | **会話履歴を保持し、毎リクエストに全量含める** | [ADR-0008](../../ADR/0008-会話用APIの構成.md)（サーバーはステートレス） | **リロードすると会話が失われる。** S-08 で離脱時の警告を出すかを決める必要がある |
| 2 | **音声を IndexedDB に一時保持する** | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) | 保持期間・破棄のタイミングを決める必要がある |
| 3 | **定量スコア（話速・フィラー数）の点数化** | [ADR-0009](../../ADR/0009-評価方式.md) | **「284文字/分は何点か」の基準がフロント側に置かれる。** S-14 の項目別スコアの出所がフロントとサーバーに分かれる |
| 4 | **評価完了までのポーリング** | [ADR-0008](../../ADR/0008-会話用APIの構成.md)（非同期評価） | S-14 に**処理中の表示**が要る。`failed` の扱いも要る |
| 5 | **ターン数の上限管理** | [ADR-0008](../../ADR/0008-会話用APIの構成.md)（終了フラグを持たない） | S-08 で**何ターンで打ち切るか**を画面仕様として決める必要がある |
| 6 | **最初の質問の固定文字列** | [ADR-0008](../../ADR/0008-会話用APIの構成.md)（`start` は任意） | S-08 / S-03 の初期表示をフロントが持つ |
| 7 | **VAD（無音 2〜3秒）と手動停止ボタンの併用** | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) | S-08 の録音 UI の仕様に直結する |

**3 と 5 は「画面の仕様」として決めないと実装できない。** [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) の残りの範囲（各画面の詳細仕様）で扱う。

| 画面 | 現在の記述 | 見直しの内容 | 根拠 |
|---|---|---|---|
