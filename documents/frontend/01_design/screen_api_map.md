## 1. 本書の位置づけ

**[画面一覧](screen_list.md) の各画面がどの API を呼ぶかを定める。** [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) の完了条件「画面と API の対応表があり、[必要api .md](<../../必要api .md>) との過不足が洗い出されている」に対応する。

**API そのものの定義は [必要api .md](<../../必要api .md>) が正本である。** 本書は画面の側から API を辿るための対応表であり、API の入出力を二重に持たない。

> 画面の側から検算した結果、**画面が要求するのに API 側に口がないもの**が6件見つかった（質問強度の受け渡し、応募情報の一覧取得、評価履歴の横断取得など）。**いずれも 2026-08-16 に決着し、[必要api .md](<../../必要api .md>) に反映済みである。**

## 3. 画面と API の対応表

**実装範囲**は [ユースケース](../../ユースケース・ユーザーフロー.md) 2.2 に、**画面 ID** は [画面一覧](screen_list.md) に対応する。**各 API の入出力は [必要api .md](<../../必要api .md>) を参照すること。**

| 画面ID | 画面名 | 実装範囲 | 契機 | 呼ぶ API |
|---|---|---|---|---|
| S-01 | サインイン | 作る | サインインする | `POST /token` |
| S-03 | チュートリアル | 作る（S-08 を流用） | 画面表示 | （なし。最初の質問は固定文字列） |
| S-03 | | | 回答する（音声） | `POST /interviews/stt` |
| S-03 | | | 終える | `POST /evaluations`（**企業IDなし**）→ `GET /evaluations/{id}` をポーリング |
| S-04 | ホーム | 作る | 画面表示 | `GET /evaluations`（全件から直近を拾う） |
| S-05 | モード選択 | 作る | 画面表示 | 応募企業情報 List |
| S-05 | | | 開始する | （なし。選択内容を S-08 に引き継ぐ） |
| S-06 | 応募企業情報 一覧 | 作る | 画面表示 | 応募企業情報 List |
| S-06 | | | 削除する | 応募企業情報 Delete |
| S-07 | 応募企業情報 登録 / 編集 | 作る | 編集で開く | 応募企業情報 Read |
| S-07 | | | 保存する | 応募企業情報 Create / Update |
| S-08 | 実践 - 本番モード | **最優先** | 画面表示 | `POST /interviews/start`（**任意**。当面はフロントの固定文字列） |
| S-08 | | | 回答する（音声） | `POST /interviews/stt` → `POST /interviews/chat` |
| S-08 | | | 回答する（文字入力） | `POST /interviews/chat`（**STT を経由しない**） |
| S-08 | | | 面接官の発言を読み上げる | `POST /interviews/tts`（**任意**。作らない場合は文字表示のみ） |
| S-08 | | | 面接を終える | `POST /evaluations` |
| S-09〜S-13 | 実践 - 練習モード（サブ機能含む） | **画面モックのみ** | — | **なし** |
| S-14 | 評価 - 合否判定 | 作る | 画面表示 | `GET /evaluations/{evaluation_id}`（`completed` になるまでポーリング） |
| S-16 | 履歴一覧 | 作る | 画面表示 | `GET /evaluations`（全件。**チュートリアルの結果も含まれる**） |
| S-16 | | | 結果を開く | `GET /evaluations/{evaluation_id}` |

**S-02 / S-15 は欠番のため本表に現れない**（[画面一覧](screen_list.md) 4章）。

### 呼び出しの要点

- **`POST /interviews/chat` には、企業ID・質問の強度・会話履歴を毎ターン送る。** サーバーが会話状態を持たないため
- **`POST /interviews/stt` は毎ターン呼ばれるとは限らない。** 文字入力のターンは STT を経由せず `chat` に直接届く
- **合否の目安は API から返らない。** S-14 が総合スコアから判定する（当面はハードコード）
- **全 API に `Authorization: Bearer <access_token>` を付ける。** トークンが無効なら S-01 へ戻す（挙動の定義は [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) の共通仕様）

## 4. フロントエンドが担う責務

**[ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md)〜[ADR-0009](../../ADR/0009-評価方式.md) の決定により、従来サーバー側に置かれることの多い処理がフロントに移っている。** 画面仕様に直接効くため列挙する。

| # | 責務 | 根拠 | 画面仕様への影響 |
|---:|---|---|---|
| 1 | **会話履歴と質問の強度を保持し、毎リクエストに含める** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | **リロードすると会話が失われる。** S-08 で離脱時の警告を出すかを決める必要がある |
| 2 | **音声を IndexedDB に一時保持する** | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) | 保持期間・破棄のタイミングを決める必要がある |
| 3 | **定量スコア（話速・フィラー数）の点数化** | [ADR-0009](../../ADR/0009-評価方式.md) | **「284文字/分は何点か」の基準がフロント側に置かれる。** S-14 の項目別スコアの出所がフロントとサーバーに分かれる |
| 4 | **評価完了までのポーリング** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | S-14 に**処理中の表示**が要る。`failed` の扱いも要る |
| 5 | **ターン数の上限管理** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | S-08 で**何ターンで打ち切るか**を画面仕様として決める必要がある |
| 6 | **最初の質問の固定文字列** | [ADR-0008](../../ADR/0008-会話用APIの構成.md) | S-08 / S-03 の初期表示をフロントが持つ |
| 7 | **VAD（無音 2〜3秒）と手動停止ボタンの併用** | [ADR-0007](../../ADR/0007-会話音声の取得と保存方式.md) | S-08 の録音 UI の仕様に直結する |
| 8 | **合否の目安の判定** | [必要api .md](<../../必要api .md>) 評価結果取得API | S-14 が総合スコアから判定する。**基準は当面ハードコード** |

**3・5・8 は「画面の仕様」として決めないと実装できない。** [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) の残りの範囲（各画面の詳細仕様）で扱う。
