# S-06 応募企業情報 一覧

## 1. 位置づけ

**登録済みの応募企業情報を一覧し、追加・編集・削除の起点になる。**

| 項目 | 内容 |
|---|---|
| 遷移元 | S-04（一覧を見る）、S-07（保存 / 取り消し）、ヘッダーのナビ「応募先企業」 |
| 遷移先 | S-07、S-04 |
| ヘッダー | グローバル（現在地: **応募先企業**） |
| コンテンツ幅 | 1080px |
| 実装範囲 | 今回 |

**削除はこの画面で完結する。** 編集・追加は S-07 で行う。

## 2. 画面の構成

| 領域 | 内容 |
|---|---|
| 見出し | 左に `応募企業情報` と説明文、右に `企業を追加` ボタン |
| 一覧 | 表形式のカード |
| 戻る | 一覧の下に `ホームに戻る` |

説明文は `企業ごとの情報と、応募者自身の経歴をまとめて登録します。質問の生成に使われます。`

## 3. 一覧の項目

| 列 | 内容 |
|---|---|
| 企業名 | 企業名を表示する |
| 登録済みの情報 | 入力済みの区分を `/` で連ねる（例: `募集要項 / 志望動機 / 経歴`） |
| 操作 | `編集`（→ S-07）と `削除`。**削除は危険色**（`#b3261e`） |

**日付の列は持たない。** API が返す `created_at` はレスポンス専用メタデータであり、この画面の表示に使わないためである。

### 3.1 「登録済みの情報」の作り方

**入力済みの項目を、下表の区分名に置き換えて並べる。**

| 区分名 | 対応する入力項目 |
|---|---|
| 募集要項 | 募集要項 URL、募集要項の要約のいずれか |
| 志望動機 | 志望動機 |
| 経歴 | 経歴・実績 |
| 備考 | 備考 |

**企業名は区分に数えない。** 企業名は必須で、左の列に出るためである。

**区分が1つだけのときは `<区分名>のみ` と書き、注意色（`#c47f0f`）で示す**（例: `経歴のみ`）。入力が少ないと質問が具体的にならないためである。**区分が0のときは `未入力` とし、同じ色で示す。**

### 3.2 並び順

**API が返した順にそのまま並べる。** 並び替えの操作は持たない。

## 4. 操作

| 操作 | 挙動 |
|---|---|
| 「企業を追加」 | S-07 を新規登録として開く。**戻り先は S-06** |
| 「編集」 | S-07 をその企業の編集として開く。**戻り先は S-06** |
| 「削除」 | 確認を出したうえで削除する（5章） |
| 「ホームに戻る」 | S-04 |

## 5. 削除

**確認なしには消さない。** 「削除」を押すと確認を出す。

| 項目 | 内容 |
|---|---|
| 文面 | `<企業名> を削除します。登録した内容は元に戻せません。` |
| ボタン | `削除する`（危険色） / `取り消す` |
| 削除に成功 | 一覧を取り直し、上部に `<企業名> を削除しました。` を出す |
| 削除に失敗 | 一覧の上部に赤字で `削除できませんでした。時間をおいてもう一度お試しください。` |

**過去の評価結果は削除しない。** 履歴（S-16）には削除した企業の結果も残る（[S-16 の詳細仕様](S-16_履歴一覧.md)）。

## 6. 状態

| 状態 | 表示 |
|---|---|
| 読み込み中 | 一覧の行をスケルトンにする |
| **0件** | 表の代わりに `登録された企業がありません。企業を追加すると、その内容をもとに面接の質問が作られます。` と `企業を追加` を出す |
| 取得に失敗 | カードの中に「読み込めませんでした」と「再読み込み」を出す |

## 7. 呼ぶ API

| 契機 | API |
|---|---|
| 画面表示 | `GET /companies` |
| 削除 | `DELETE /companies/{company_id}` |

**本画面のために API へ加える項目はない**（[画面と API の対応](../screen_api_map.md) 6章）。
