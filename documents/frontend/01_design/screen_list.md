## 1. 本書の位置づけ

**本サービスが持つ画面をすべて列挙し、各画面の役割と主な表示情報を定める。** [ユースケース・ユーザーフロー.md](../../ユースケース・ユーザーフロー.md) が定めた「機能とその順序」を、何画面でどう見せるかに落としたものである。画面と画面のつながりは [画面遷移図](screen_flow.md) が担う。

### 本書で決めないこと

| 決めないこと | 扱う Issue |
|---|---|
| 各画面の詳細仕様（入力項目・バリデーション・レイアウト） | [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) および画面ごとの実装 Issue |
| 画面と API の対応 | [#9](https://github.com/study-basic-hackathon/hanasu/issues/9)（[画面と API の対応](screen_api_map.md)で確定済み） |
| 共通仕様（未認証時のリダイレクト、エラー表示、ローディング表示、マイク許可が拒否された場合の挙動） | [#9](https://github.com/study-basic-hackathon/hanasu/issues/9) |
| UI ライブラリ・レスポンシブ対応の方針 | [#16](https://github.com/study-basic-hackathon/hanasu/issues/16) |
| 応募企業情報の項目定義 | [#17](https://github.com/study-basic-hackathon/hanasu/issues/17) |

## 2. 前提

| # | 前提 | 出典 |
|---:|---|---|
| 1 | **PC のブラウザで利用する。** スマートフォン向けのレイアウトは持たない | [ユースケース](../../ユースケース・ユーザーフロー.md) 前提1 |
| 2 | 認証済みユーザーのみが利用できる | 同 前提2 / [必要api .md](<../../必要api .md>) API制約 |
| 3 | **会員登録は作らない。** 固定の ID / パスワード1組でログインし、**ユーザーは1つだけ** | [ADR-0011](../../ADR/0011-会員登録と利用アカウント.md) |
| 4 | **プロフィールという独立した登録を持たない。** 応募者自身の情報は応募企業情報に含める | [ユースケース](../../ユースケース・ユーザーフロー.md) 2.2 |
| 5 | **本番モードを最優先で作り上げ、練習モードは画面のモックのみ作る** | 同上 |
| 6 | **評価指標は話の速さ・フィラーの数・構成/内容の3つ**（任意で間の長さ）。**「抑揚」「滑舌」「声の大きさ」は評価しない** | [ADR-0009](../../ADR/0009-評価方式.md) |
| 7 | **評価は非同期。** 結果が出るまで画面がポーリングする | [ADR-0008](../../ADR/0008-会話用APIの構成.md) |

対応デバイスを PC のみとする判断そのものは [#16](https://github.com/study-basic-hackathon/hanasu/issues/16) の完了条件「レスポンシブ対応の要否」に属し、ADR は #16 で記録する。本書はその前提の上に立つ。

## 4. 画面 ID の新旧対応

画面 ID は遷移順に振り直している。チームで共有されている「面接対策アプリ 画面要件定義書 / 基本設計書(画面イメージ)」の S-01〜S-08 との対応は下表のとおり。

| 旧ID（要件定義書・基本設計書） | 旧画面名 | 新ID | 新画面名 |
|---|---|---|---|
| S-01 | サインイン / 会員登録 | S-01 | **サインイン**（会員登録は持たない） |
| S-02 | プロフィール登録 | — | **持たない**（S-07 に集約） |
| S-03 | チュートリアル(初期評価) | S-03 | チュートリアル（**S-08 の画面を流用**） |
| S-04 | モード選択 + 質問強度 + 企業選択 | S-05 | モード選択 |
| S-05 | 企業登録 | S-07 | 応募企業情報 登録 / 編集 |
| S-06 | 実践 - 練習モード | S-09 | 実践 - 練習モード（サブ機能は S-10〜S-13 に分割） |
| S-07 | 実践 - 本番モード | S-08 | 実践 - 本番モード |
| S-08 | 評価 - 合否判定 | S-14 | 評価 - 合否判定 |
| — | — | S-04 | ホーム（新規） |
| — | — | S-06 | 応募企業情報 一覧（新規） |
| — | — | S-16 | 履歴一覧（新規） |

**S-02 / S-15 は欠番として残す。** 番号を詰めると [画面遷移図](screen_flow.md) や [画面と API の対応](screen_api_map.md) の参照がすべて変わるため（[ユースケース](../../ユースケース・ユーザーフロー.md) の UC-02 を欠番として残しているのと同じ方針）。

旧資料はスマートフォンのワイヤーフレームとして描かれているが、**前提1のとおり対応デバイスは PC のみ**であり、レイアウトは引き継がない。引き継ぐのは画面の粒度と、画面上に置く要素である。

## 5. 今回は持たない画面

| 画面 | 持たない理由 |
|---|---|
| **会員登録** | **固定の ID / パスワード1組で利用するため**（[ADR-0011](../../ADR/0011-会員登録と利用アカウント.md)）。サインアップの API・画面とも作らない |
| パスワード再設定 | 会員登録自体を作らないため。**サインインできなくなった場合の復旧手段は持たない** |
| **プロフィール登録 / 編集** | **応募企業情報（S-07）に集約したため**（[ユースケース](../../ユースケース・ユーザーフロー.md) 2.2）。面接の質問生成に必要な情報は応募する企業ごとに変わるため、1画面にまとめる |
| 設定（ハブ）画面 | プロフィールを独立して持たなくなったことで、**設定項目そのものがなくなった** |
